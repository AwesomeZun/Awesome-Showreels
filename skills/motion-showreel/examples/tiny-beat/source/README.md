# Tiny Beat

> 매일 한 곡, 나만의 리듬.

책상 위에 올려 둔 작은 그루브박스를 브라우저로 옮긴 음악 실험입니다. 16스텝 드럼과 멜로디를 찍고, 날짜로 정해지는 "오늘의 비트"를 굴려 보고, 보관함 달력에 하루 한 곡씩 쌓을 수 있어요. 모든 소리는 샘플 파일 없이 Web Audio로 그 자리에서 합성합니다.

toyz 마켓플레이스의 예시 프로젝트 "Tiny Beat"를 실제 앱으로 구현했습니다.

## 주요 기능

- **16스텝 시퀀서**: 드럼 4트랙(킥, 스네어, 하이햇, 클랩)은 오실레이터·노이즈·엔벌로프로 합성하고, 멜로디 2트랙(베이스, 리드)은 선택한 스케일의 음만 보이는 피아노롤(1~2옥타브)에서 음 높이를 고릅니다.
- **정확한 재생**: `AudioContext.currentTime` 기준 lookahead 스케줄러(25ms 타이머, 기본 100ms 선행 예약)로 재생합니다. 메인 스레드가 바빠 타이머가 늦게 불리면 선행 예약을 최대 300ms까지 잠시 늘렸다가 다시 줄입니다. BPM 60~180, 스윙 0~60%를 지원하고, 화면의 재생 헤드는 `getOutputTimestamp()`로 출력 지연을 보정해 실제로 들리는 스텝을 표시합니다.
- **믹서**: 트랙별 음량·뮤트·솔로, 마스터 음량, 마스터 컴프레서(`DynamicsCompressorNode`, 강도 노브와 게인 리덕션 미터), 리드용 딜레이(점 8분)와 리버브(절차적으로 만든 임펄스의 `ConvolverNode`) 센드.
- **스텝 입력**: 클릭·탭으로 토글, 드래그로 연속 칠하기, 강세 2단계(일반·강). 강세는 `강세` 버튼을 켜거나 Shift를 누른 채 찍습니다. 키보드로는 방향키로 칸을 옮기고 Enter로 찍습니다.
- **패턴 A/B/C/D**: 전환(재생 중에는 다음 마디에 바뀝니다), 복사·지우기(되돌리기 가능), 최대 8칸 체인 재생(예: A → A → B → A)과 "재생 따라가기".
- **오늘의 비트**: 장르는 방향키로도 고를 수 있습니다. 날짜·장르·굴림 번호를 시드로 한 결정적 난수로 곡을 만듭니다. 같은 날, 같은 장르, 같은 굴림 번호면 어느 브라우저에서든 같은 비트가 나옵니다. 장르 프리셋은 로파이, 하우스, 브레이크, 앰비언트이며 각각 킥·스네어 배치, BPM, 스윙, 스케일, 센드 양에 대한 규칙이 다릅니다.
- **보관함**: 곡 이름을 붙여 저장(덮어쓰기·사본), 날짜별 달력 표시와 연속 기록, 불러오기, 복제, 삭제(되돌리기), 곡별 공유 링크 복사.
- **공유 링크**: 곡 전체(패턴 4개, 확률, 체인, 믹서, 음색, 스케일, 이름)를 비트 단위로 압축해 URL 해시(`#/s/...`)에 담습니다. 해시 부분은 패턴 2개짜리 곡이 130자 안팎, 패턴 4개를 모두 채우고 확률까지 넣어도 260자 안팎입니다. 링크를 열면 곡이 바로 실리고 "바로 재생" 버튼이 보이며, 원래 하던 작업은 따로 보관돼 되돌릴 수 있습니다.
- **WAV 내보내기**: `OfflineAudioContext`로 루프를 1·2·4회 렌더링해 16비트 PCM 스테레오 44.1kHz WAV로 내려받습니다. 파일 길이는 `스텝 수 × (60 / BPM / 4) × 반복 수`와 샘플 단위로 정확히 같습니다.
- **시각화와 단축키**: LCD는 멈춰 있을 때 지금 패턴을 6행 × 16열 LED 행렬로 보여 주고, 재생 중에는 그 위에 `AnalyserNode` 스펙트럼(세그먼트 막대)과 파형을 겹쳐 그리며 재생 중인 열과 박자 LED 네 칸을 밝힙니다. `Space` 재생·정지, `1`~`4` 패턴 선택.
- **모바일**: 좁은 화면과 터치 태블릿에서는 트랙을 고른 뒤 16스텝을 4×4 큰 패드로 찍습니다(패드마다 44px 이상). 피아노롤은 휴대폰 폭에서 4스텝씩, 좁은 창·터치 태블릿에서 8스텝씩 페이지로 나눠 칸이 44px 아래로 줄지 않게 하고, 재생 헤드가 있는 페이지 버튼에 LED를 켭니다. 휴대폰에서 대화상자는 화면 아래에서 올라오는 시트로 열립니다. 포인터를 누르는 순간 바로 반영되고, 첫 터치에서 오디오 잠금을 풉니다. 화면 아래 도크에서 언제든 재생·정지와 패턴 전환을 할 수 있고, 재생 중에 보관함·설정으로 가면 머리글에 `재생 정지` 버튼이 나타나요.
- **추가 기능**: 트랙별 음색 프리셋(트랙당 3종), 스텝별 확률(100·75·50·25%, `확률 편집` 모드).
- **데이터 관리**: JSON 내보내기·가져오기(5MB 이하, 곡이 없는 파일은 거절), 예시 데이터 지우기, 전체 초기화(확인 절차).

## 사용 방법

1. 처음 열면 오늘의 로파이 비트와 예시 곡 4개가 들어 있어요. 재생 버튼이나 `Space`를 누르면 바로 들을 수 있어요.
2. 패드를 눌러 스텝을 켜고 끄세요. 누른 채 옆으로 끌면 이어서 칠해집니다.
3. 베이스·리드는 시퀀서 행을 눌러 음을 넣은 뒤, 아래 피아노롤에서 음 높이를 고르세요.
4. 도넛 모양 템포 다이얼은 위아래로 끌거나 휠·방향키로 돌립니다. 더블클릭하면 기본값으로 돌아가요.
5. 마음에 들면 `저장`으로 이름을 붙여 보관함에 남기고, `공유`로 링크를 보내거나 `WAV`로 파일을 받으세요.

## 실행·빌드·테스트

```sh
npm install --no-audit --no-fund
npm run dev          # 개발 서버
npm run build        # 타입 검사 + 프로덕션 빌드(dist/)
npm run lint         # oxlint
npm run test:unit    # 도메인 로직 단위 테스트(node --test, 21개)
PORT=4305 npm run test:smoke   # 빌드 결과를 미리보기 서버로 띄워 헤드리스 Chrome으로 사용자 흐름 24단계를 확인
```

스모크 테스트는 시스템에 설치된 Chrome을 `playwright-core`의 `channel: 'chrome'` 헤드리스 모드로 씁니다. 확인하는 내용은 다음과 같습니다.

- 재생 중 매 프레임 화면의 재생 헤드와 "지금 들리는" 스텝 비교, 출력 레벨 확인
- 재생 중 BPM·스윙을 바꿔도 예약 간격이 끊기지 않는지, 정지 0.6초 뒤 출력 RMS가 0에 가까운지
- 공유 링크를 새 브라우저 컨텍스트에서 열었을 때 인코딩 결과가 원본과 글자 단위로 같은지
- 내려받은 WAV의 RIFF 헤더(형식, 채널, 샘플레이트, 비트 수, 청크 크기)와 프레임 수가 BPM·반복 수와 맞는지
- 자동 재생 허용 플래그 없이 띄운 모바일 브라우저에서 첫 터치로 오디오가 켜지는지
- 저장·복제·삭제·되돌리기·새로고침 후 유지, JSON 내보내기·가져오기(큰 파일·빈 파일 거절), 전체 초기화, 가로 넘침
- QA 회귀 시나리오: 음역을 줄인 뒤 찍은 음이 피아노롤에 보이는지, 대화상자를 닫은 뒤 포커스 복귀, 재생·정지 연타, 보관함에서 재생 정지, 건너뛰기 링크, 같은 공유 링크 다시 열기와 원래 작업 보존, 모바일 터치 대상 44px

스크린샷은 `tests/artifacts/`에 남습니다(저장소에는 올리지 않습니다).

## 기술 구성

- Vite 8, React 19, TypeScript 6(strict), oxlint, playwright-core(스모크 테스트)
- 서체: Pretendard Variable(본문), JetBrains Mono Variable(라벨·숫자) — 모두 자체 호스팅
- 외부 오디오·압축 라이브러리 없음. 합성, 스케줄러, 비트 패킹 코덱, WAV 인코더, 결정적 난수(mulberry32 + FNV-1a)를 직접 구현했습니다.

```text
src/
  domain/    순수 로직: 곡 모델·정규화, 스케일·음 옮기기, 생성기, 코덱, 보관함, 날짜, WAV, 저장소
  audio/     합성 보이스, 믹서 그래프, 스텝 예약, 실시간 엔진, 오프라인 렌더
  state/     곡 리듀서(순수 함수)와 스튜디오 상태 공급자
  hooks/     드래그 칠하기, 로빙 포커스, 재생 헤드, 해시 라우팅 등
  components/ 콘솔(도넛 다이얼·LCD·트랜스포트), 시퀀서, 4×4 패드, 피아노롤, 믹서, 대화상자
  views/     그루브박스, 보관함, 설정
```

화면 전환은 해시 라우팅(`#/`, `#/library`, `#/settings`, 공유 링크 `#/s/...`)이라 서버 rewrite 설정이 필요 없습니다.

## 데이터 저장 방식과 개인정보

- 모든 데이터는 이 브라우저의 `localStorage`에만 저장합니다. 키는 `toyz-tiny-beat:library`, `:draft`, `:prefs`, `:backup`이며 모두 스키마 버전 필드(`v`)를 둡니다. 저장된 값이 손상되면 읽을 수 있는 부분만 살리고 나머지는 기본값으로 채웁니다.
- 서버, 계정, 분석 도구, 외부 네트워크 호출이 없습니다. 공유 링크의 곡 데이터도 URL 해시에만 들어 있어 서버로 전송되지 않습니다.
- 예시 곡 이름(퇴근길 네온, 새벽 편의점 등)은 모두 가상의 것입니다.

## 알려진 한계

- iPhone은 무음 모드 스위치가 켜져 있으면 Web Audio 소리가 나지 않을 수 있습니다.
- 멜로디는 스텝마다 음 하나(모노포닉)입니다. 음 길이는 다음 음까지(최대 4스텝) 자동으로 정해집니다.
- 브라우저가 탭을 오래 멈췄다가 깨우면 밀린 스텝을 몰아서 재생하지 않고 현재 시각부터 다시 맞춥니다.
- 확률 스텝은 실시간 재생에서는 매번 다르게 울리고, WAV 렌더링은 고정 시드를 써서 같은 곡이면 늘 같은 결과가 나옵니다.
- WAV는 루프 길이에 정확히 맞춰 자르므로 마지막 스텝의 잔향 꼬리는 잘립니다(파일을 이어 붙여 반복하기 쉽게 하기 위해서입니다).
- 마우스를 쓰는 좁은 창(약 1000px 이하)에서는 16열 패드가 44px보다 작아질 수 있습니다. 터치 기기와 760px 이하 화면에서는 4×4 큰 패드로 바뀝니다.
- 저장된 데이터나 가져온 파일, 공유 링크에 지금 음역(스케일·옥타브)보다 높은 음이 있으면 옥타브 단위로 내려 음역 안에 넣습니다.
- 공유 링크를 연달아 열면 "이전 작업으로 돌아가기"는 처음 링크를 열기 직전의 작업으로 돌아갑니다.
- "오늘"과 연속 기록은 기기의 현지 날짜를 기준으로 합니다.
