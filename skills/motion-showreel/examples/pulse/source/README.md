# Pulse

메이커를 위한 작고 선명한 대시보드입니다. 여러 프로젝트의 할 일과 배포 메모를 한곳에서 관리하는 작업 공간으로, 숫자와 상태가 한눈에 들어오는 계기판을 목표로 만들었습니다.

toyz 마켓플레이스의 예시 프로젝트 “Pulse”를 실제로 동작하는 웹앱으로 구현했습니다. 백엔드와 계정 없이 브라우저 안에서 모든 기능이 완결됩니다.

## 주요 기능

- **대시보드(계기판)**: 지난 마감·오늘 마감·이번 주 마감·진행 중·이번 주 완료·최근 30일 배포를 숫자와 레벨 미터(10칸 눈금)로 보여 줍니다. 아래에는 마감 레이더(지난 마감 / 오늘 / 이번 주 남은 날), 프로젝트별 진행률 링, 최근 배포 5건, 최근 12주 활동 히트맵(완료와 배포 기록 기반), 프로젝트 상태 분포가 있습니다. 차트는 모두 SVG로 직접 그렸습니다.
- **프로젝트**: 이름, 한 줄 설명, 색, 상태(아이디어·개발 중·출시·보류), 저장소와 배포 링크를 만들고 고치고 지울 수 있습니다. 보관하면 대시보드와 목록에서 빠지고, 보관함에서 다시 꺼낼 수 있습니다. 삭제 직후에는 알림에서 되돌릴 수 있습니다.
- **할 일**: 제목, 우선순위(높음·보통·낮음), 마감일, 메모, 상태(할 일·진행 중·완료), 반복(매일·매주·매월)을 다룹니다.
  - 칸반 3열 보드에서 끌어서 순서와 상태를 바꿉니다. 포인터 이벤트 기반이라 마우스·터치·펜이 같은 코드로 동작합니다. 터치에서는 카드 왼쪽 손잡이로 끕니다.
  - 키보드 대안: 카드 제목에서 `Alt`+`←`/`→`로 상태, `Alt`+`↑`/`↓`로 순서를 바꿉니다. 카드의 ⋯ 메뉴에서도 상태 변경과 위·아래 이동을 할 수 있습니다.
  - 목록 보기로 바꾸면 행마다 상태 선택 상자가 있고, 직접 정한 순서·마감 빠른 순·우선순위 높은 순으로 정렬할 수 있습니다.
  - 검색(제목·메모), 우선순위·프로젝트 필터, 완료 항목 숨기기를 제공합니다.
- **배포 메모(릴리스 로그)**: 버전, 날짜, 환경(production·preview), 여러 줄 변경 내용, 결과(성공·롤백)를 남깁니다. 프로젝트별 타임라인과 전체 타임라인이 있고, 프로젝트를 고르면 가장 큰 버전의 patch를 하나 올린 다음 버전을 제안합니다.
- **빠른 추가 구문**: `로그인 버그 고치기 !높음 @Loopdeck 내일`처럼 적으면 제목·우선순위·프로젝트·마감일을 해석해 미리보기 칩으로 보여 준 뒤 추가합니다.
- **커맨드 팔레트(`⌘K` / `Ctrl+K`)**: 프로젝트 이동, 할 일 빠른 추가(같은 구문), 배포 메모 추가, 칸반·목록 보기 전환, 완료 숨기기, 보관함 보기, 내보내기, 할 일 검색을 한곳에서 합니다.
- **데이터 관리**: JSON 내보내기·가져오기(합치기 또는 통째로 바꾸기, 가져오기 전 개수 미리보기), 예시 데이터만 지우기, 예시 데이터 다시 넣기, 전체 초기화(직후 되돌리기 가능).
- **있으면 좋은 기능**: 이번 주 작업 리포트를 마크다운으로 복사하기(대시보드 오른쪽 위 버튼, 팔레트), 할 일 반복 설정.

## 사용 방법

1. 처음 열면 가상의 예시 프로젝트 6개(하나는 보관됨)와 할 일, 배포 기록이 들어 있어 바로 둘러볼 수 있습니다.
2. 대시보드 위쪽 입력창이나 `⌘K`로 할 일을 빠르게 추가합니다. 프로젝트를 적지 않으면 지금 보고 있는 프로젝트, 없으면 마지막으로 쓴 프로젝트에 들어갑니다.
3. 프로젝트 화면의 “배포 메모” 버튼에는 다음 버전이 미리 적혀 있습니다.
4. 실제로 쓰기 시작할 때는 **설정 → 예시 데이터 지우기**를 누르면 직접 만든 항목은 남기고 예시만 지웁니다.

### 빠른 추가 구문

| 적는 방법 | 뜻 |
| --- | --- |
| `!높음` `!보통` `!낮음` (`!high` `!h` `!low` 등) | 우선순위 |
| `@프로젝트이름` | 프로젝트. 공백이 든 이름도 되고, 앞부분만 적어도 맞춰 봅니다(`@kite` → Kite Forms). |
| `오늘` `내일` `모레` `글피` | 상대 날짜 |
| `3일 뒤` `2주 후` | N일·N주 뒤 |
| `금요일` / `이번주 금요일` / `다음주 월요일` | 요일(오늘 포함 가장 가까운 그 요일) |
| `이번주` / `다음주` | 이번 주 일요일 / 다음 주 월요일 |
| `9/30` `9월 30일` | 올해 그 날짜. 이미 지났으면 내년으로 넘깁니다(연말에 `1/2`를 적으면 다음 해 1월 2일). |
| `30일` | 이번 달 30일. 지났으면 그 날짜가 있는 다음 달로 넘깁니다. |
| `2026-10-03` `2026.10.3` | 그 날짜 그대로 |

뒤에 `까지`를 붙여도 됩니다(`내일까지`). 존재하지 않는 날짜(`2/30`)나 단어 안에 섞인 숫자(`v1/2`)는 날짜로 보지 않고 제목에 남깁니다.

## 실행·빌드·테스트

```sh
npm install --no-audit --no-fund
npm run dev          # 개발 서버
npm run build        # 타입 검사 + 프로덕션 빌드(dist/)
npm run lint         # oxlint
npm run test:domain  # 도메인 로직 검증(날짜 해석 경계, 시간대, 칸반 순서, 히트맵 집계 등)
PORT=4302 npm run test:smoke  # 빌드본을 헤드리스 Chrome으로 띄워 사용자 흐름을 확인합니다
```

스모크 테스트는 로컬에 설치된 Chrome을 `playwright-core`의 `channel: 'chrome'` 헤드리스 모드로 씁니다. 대시보드 숫자, 빠른 추가 구문, 프로젝트 만들기·고치기·보관·삭제·되돌리기, 마우스 끌어 놓기와 새로고침 후 순서 유지, 키보드 상태 변경과 포커스 유지, 목록 보기와 필터, 배포 메모와 다음 버전 제안, 히트맵 갱신, 리포트 복사, 커맨드 팔레트, 내보내기·초기화·가져오기, 손상된 저장 데이터 복구, UTC+14 시간대, 모바일 가로 넘침과 터치 끌기, 터치 대상 크기를 확인합니다. QA에서 찾은 문제(팔레트를 쓴 뒤 편집 창이 닫히지 않던 문제, 건너뛰기 링크, 반복 회차 중복, 가져온 링크 검증, 저장 실패 경고, 탭 사이 쓰기 되풀이 등)는 회귀 시나리오로 함께 돌립니다. 스크린샷은 `tests/artifacts/`에 남습니다.

## 기술 구성

- Vite 8, React 19, TypeScript 6(strict), oxlint, playwright-core(테스트 전용)
- 본문 서체 Pretendard Variable(패키지로 자체 호스팅). 외부 CDN·폰트 링크·네트워크 호출이 없습니다.
- 추가 런타임 의존성은 없습니다. 드래그 앤 드롭, 커맨드 팔레트, 차트, 날짜 해석을 모두 직접 구현했습니다.
- 해시 라우팅(`#/`, `#/projects/:id`, `#/projects/:id/releases`, `#/todos`, `#/releases`, `#/settings`)이라 서버 rewrite 설정이 필요 없습니다.

```text
src/
  domain/      순수 함수: 날짜·구문 해석·칸반 순서·통계·히트맵·semver·가져오기 검증·예시 데이터
  store/       리듀서와 localStorage 저장(손상 복구, 다른 탭 동기화)
  app/         편집 창 컨텍스트, 되돌리기 토스트가 붙은 동작, 파일·클립보드 도우미
  hooks/       해시 라우팅, 포인터 드래그, 자정 넘김 감지
  components/  셸, 빠른 추가, 커맨드 팔레트, 칸반·목록, 타임라인, 편집 창, SVG 차트, 크롬 방울 그림
  pages/       대시보드, 프로젝트 목록·상세, 전체 할 일, 배포 타임라인, 설정
  styles/      토큰과 화면별 스타일
```

### 날짜와 시간대

마감일과 배포 날짜는 시간 없이 `YYYY-MM-DD` 문자열(기기 시간대의 달력 날짜)로 저장합니다. 문자열을 `new Date('YYYY-MM-DD')`로 바로 읽으면 UTC로 해석되어 하루가 밀릴 수 있어서, 항상 로컬 자정으로 바꾸는 함수를 거칩니다. 완료 시각은 ISO 시각으로 저장하고, 히트맵과 “이번 주 완료”를 셀 때 기기 시간대의 날짜로 바꿔 셉니다. 자정을 넘기면 화면의 “오늘”이 자동으로 바뀝니다. 도메인 테스트는 여러 시간대(`TZ=UTC`, `America/Los_Angeles`, `Pacific/Kiritimati` 등)에서 같은 결과를 내는지 확인했습니다.

## 데이터 저장 방식과 개인정보

- 모든 데이터는 이 브라우저의 `localStorage` 키 `toyz-pulse:data`에 스키마 버전(`schemaVersion: 1`)과 함께 저장합니다.
- 저장된 값이 손상되어 읽을 수 없으면 원본을 `toyz-pulse:data.corrupt`에 옮겨 두고 예시 데이터로 새로 시작하며, 화면에 안내를 띄웁니다.
- 저장 공간이 가득 찼거나 사생활 보호 모드라서 저장에 실패하면 어느 화면에서든 본문 위에 경고를 띄우고, 넓은 화면의 위쪽 막대 표시등도 초록(`SAVED · LOCAL`)에서 빨강(`SAVE FAILED`)으로 바뀝니다. 다음 저장이 성공하면 경고가 사라집니다.
- 가져온 파일이나 저장된 데이터의 저장소·배포 링크는 `http(s)` 주소만 받아들입니다. `javascript:`·`data:` 같은 주소는 빈 값으로 바꿉니다.
- 계정, 서버, 분석 도구가 없고 어떤 데이터도 외부로 보내지 않습니다. 저장소·배포 링크는 사용자가 누를 때만 새 창으로 열립니다.
- 브라우저 데이터를 지우면 함께 사라지므로, 중요한 데이터는 설정에서 JSON으로 내보내 두세요.

## 알려진 한계

- 기기·브라우저 사이 동기화는 없습니다. 다른 기기로 옮길 때는 JSON 내보내기·가져오기를 씁니다. 같은 브라우저의 두 탭은 저장할 때마다 서로 맞춰지지만, 두 탭에서 동시에 고치면 마지막 저장이 이깁니다.
- 마감은 날짜 단위입니다. “오후 3시” 같은 시각은 다루지 않습니다.
- 빠른 추가 구문은 위 표의 표현만 인식합니다. “다다음주”, “월말”, “다음 달” 같은 표현은 제목에 그대로 남습니다.
- 히트맵은 현재 완료 상태인 할 일의 완료 시각과 배포 기록의 날짜로 셉니다. 완료를 취소하거나 할 일을 지우면 그날의 칸에서도 빠집니다. 보관한 프로젝트는 대시보드 집계(히트맵 포함)에서 제외합니다.
- 반복 할 일은 완료하는 순간 다음 회차 하나를 만듭니다. 앞으로의 회차를 미리 만들어 두지는 않습니다. 같은 프로젝트에 같은 제목의 반복 할 일이 아직 끝나지 않은 채 있으면(완료를 취소했다가 다시 완료한 경우 등) 회차를 또 만들지 않습니다.
- 할 일 제목은 140자까지입니다. 빠른 추가에서도 같은 기준으로 막고 이유를 알려 줍니다.
- 칸반 완료 열은 처음에 최근 6건만 보이고 “더 보기”로 펼칩니다. 좁은 화면에서는 세 열이 세로로 쌓이며, 끄는 동안 화면 가장자리에서 자동으로 스크롤합니다.
- 영문 프로젝트 이름 뒤 조사(을/를 등)는 읽는 소리를 어림해서 고르므로 드물게 어색할 수 있습니다.
