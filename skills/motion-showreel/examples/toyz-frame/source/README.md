# Frame — 내 작업을 담는 가장 빠른 포트폴리오

편집기 왼쪽, 실물 미리보기 오른쪽. 사진과 작업 설명을 넣는 즉시 완성된 포트폴리오가 보이고, 이미지까지 모두 담긴 **HTML 파일 하나**로 가져갈 수 있습니다.

toyz 마켓플레이스의 예시 프로젝트 「Frame」을 실제로 동작하는 웹앱으로 구현했습니다.

## 주요 기능

- **프로필 편집**: 이름, 직함, 소개, 위치, 이메일, 링크 목록(라벨과 주소), 프로필 이미지(선택)와 대체 텍스트. 위험한 주소(`javascript:` 등)는 입력 단계에서 경고하고 결과물에서는 빠집니다.
- **작업 관리**: 제목, 연도, 역할, 분류 태그, 여러 단락의 설명(빈 줄로 구분), 대표 이미지와 추가 이미지 여러 장.
  - 이미지는 파일 선택, 끌어다 놓기, 붙여넣기(작업 편집 화면 어디서든 ⌘V/Ctrl+V)로 넣습니다.
  - 긴 변 1600px, JPEG 품질 0.82로 줄여 IndexedDB에 저장합니다(투명한 PNG는 PNG로 유지).
  - 작업과 이미지 모두 손잡이를 끌거나(마우스와 터치 모두) 위·아래 버튼으로 순서를 바꿉니다. 이미지는 별 버튼으로 대표 이미지를 지정합니다.
  - 작업·이미지·링크 삭제와 프로젝트 불러오기는 알림의 **되돌리기**로 복구할 수 있습니다.
- **템플릿 3종**: 레이아웃 자체가 다릅니다.
  - `GRID` 갤러리형: 큰 이름과 이미지 격자.
  - `EDITORIAL` 매거진형: 12칸 격자 위에 외곽선 번호와 좌우로 엇갈리는 큰 이미지, 포인트 색 구체.
  - `MONO` 목록형: 번호·썸네일·제목·역할·연도가 표처럼 정렬된 촘촘한 목록.
  - 포인트 색(프리셋 6가지와 직접 고르기), 배경 톤(밝게·어둡게), 제목 서체(굵은 산세리프·세리프·모노)를 고릅니다.
- **실시간 미리보기**: 내보내기와 **똑같은 HTML**을 iframe `srcdoc`에 그립니다. iframe 두 개를 번갈아 쓰는 이중 버퍼라서, 입력할 때마다 깜박이지 않고 스크롤 위치와 보고 있던 상세 화면이 유지됩니다.
  - 폭 전환: 데스크톱 1280, 태블릿 768, 모바일 390.
  - 편집기에서 작업을 열면 미리보기도 그 작업의 상세로 이동합니다.
- **작업 상세**: 미리보기와 내보낸 HTML 모두에서 작업을 누르면 이미지 갤러리와 설명이 있는 상세 화면으로 갑니다. 이전·다음 작업, Esc로 목록 돌아가기, 목록으로 돌아오면 방금 본 작업 위치로 스크롤합니다.
- **내보내기**
  - 단일 self-contained HTML: CSS 인라인, 이미지는 base64 data URI, 시스템 서체, 반응형. 외부 참조가 없어 인터넷 없이, 어느 폴더에서나 열립니다.
  - 예상 파일 크기(실제 파일과 1% 안쪽으로 일치), 내보내기 전 점검 목록(이름 누락, 이미지 없는 작업, 대체 텍스트 누락, 잘못된 링크)과 바로 고치러 가는 링크.
  - Open Graph 메타(`og:title`, `og:description`)와 인쇄용 스타일(모든 작업 상세를 쪽을 나눠 인쇄)을 포함합니다.
- **프로젝트 파일**: `.frame.json`에 이미지까지 담아 저장하고 불러옵니다. 다른 기기로 옮기거나 나중에 이어서 편집할 때 씁니다.
- **예시 포트폴리오**: 가상의 디자이너 「이로아」와 작업 6개. 작업 이미지는 모두 Canvas로 절차적으로 그린 크롬 조형, 궤도 격자, 모듈 서체, 파도 선입니다.
- **설정**: 저장 공간 사용량, 예시 데이터 지우기(예시에서 온 내용만 걷어내고 직접 추가한 작업·고친 항목은 남깁니다, 되돌리기 가능), 예시 다시 불러오기(되돌리기 가능), 전체 초기화(확인 절차), 손상된 저장본 복구(아래 참고).

## 사용 방법

1. **01 프로필**에서 이름과 직함, 소개를 고칩니다. 오른쪽 미리보기가 바로 바뀝니다.
2. **02 작업**에서 `작업 추가`를 누르고 제목, 설명을 적은 뒤 이미지를 끌어다 놓습니다. 이미지마다 무엇이 보이는지 대체 텍스트를 적어 주세요.
3. **03 디자인**에서 템플릿과 색, 톤, 서체를 고릅니다.
4. **04 내보내기**에서 점검 목록을 확인하고 `HTML 파일 내려받기`를 누릅니다. 받은 파일을 그대로 메일로 보내거나 정적 호스팅에 올리면 됩니다.
5. 이어서 편집하려면 같은 화면에서 `프로젝트 저장`으로 `.frame.json`을 받아 두세요.

좁은 화면(1024px 미만)에서는 화면 아래(엄지가 닿는 자리)의 `편집 / 미리보기` 버튼으로 두 화면을 오갑니다.

## 실행·빌드·테스트

```sh
npm install --no-audit --no-fund
npm run dev            # 개발 서버
npm run build          # 타입 검사 + 프로덕션 빌드(dist/)
npm run lint           # oxlint
npm run test:unit      # 도메인 로직 단위 검증(Node 22.18+ 타입 스트리핑)
PORT=4304 npm run test:smoke   # 빌드 결과를 띄워 헤드리스 Chrome으로 사용자 흐름 24가지를 확인
```

스모크 테스트는 설치된 Chrome을 `playwright-core`의 `channel: 'chrome'` 헤드리스 모드로 씁니다. 스크린샷은 `tests/artifacts/`에 남습니다.
확인하는 흐름: 첫 실행 예시, 프로필 즉시 반영과 위험한 링크 차단, 큰 이미지 축소·새로고침 유지, 붙여넣기·끌어다 놓기, 작업 순서 변경(버튼·드래그)과 삭제 되돌리기, 큰 이미지 여러 장과 저장 공간 부족 안내, 템플릿 3종의 레이아웃 차이와 색·톤·서체, 미리보기 폭과 상세 이동, 점검 목록, XSS 차단과 미리보기·내보내기 일치, 내보낸 파일을 **빈 폴더에서 오프라인으로** 열어 외부 요청 0건 확인, 프로젝트 파일 저장→전체 초기화→불러오기, 손상된 저장값 복구, 모바일 넘침과 터치 대상 크기.
QA에서 찾은 결함의 회귀 시나리오도 함께 돌립니다: 건너뛰기 링크와 화면 전환 포커스, 잘못된 주소, 예시 지우기가 내 작업을 남기는지, 긴 작업 제목에서 미리보기 틀이 잘리지 않는지와 좁은 편집기의 탭, 손상된 저장값의 이미지 보존과 되살리기, 두 탭 동시 사용, 깨진 이미지가 섞인 프로젝트 파일, 불러오기·링크 삭제 되돌리기, 프로필 이미지 붙여넣기, 모바일 전체 터치 대상 44px, 터치로 끌어 순서 바꾸기.

## 기술 구성

- Vite 8, React 19, TypeScript 6(strict), oxlint, playwright-core(테스트). 런타임 의존성은 React와 자체 호스팅 Pretendard뿐입니다.
- `src/domain/`: 순수 함수. 데이터 모델과 정규화(`project.ts`), 이스케이프(`escape.ts`), 점검 목록(`checklist.ts`), 크기 계산(`estimate.ts`), 렌더러(`render/renderPortfolio.ts`, `render/styles.ts`, `render/inlineScript.ts`).
- `src/export/`: 미리보기(blob: URL)와 내보내기(data: URI)가 같은 렌더러를 쓰도록 묶은 부분과 내려받기.
- `src/storage/`: localStorage(프로젝트), IndexedDB(이미지), `.frame.json` 직렬화.
- `src/state/`: 상태와 자동 저장, 되돌리기, 이미지 처리 흐름.
- `src/components/`, `src/panels/`: 화면. 해시 라우팅(`#/profile`, `#/works/<id>`, `#/design`, `#/export`, `#/settings`)이라 서버 rewrite 설정이 필요 없습니다.

## 데이터 저장 방식과 개인정보

- 모든 데이터는 **이 브라우저 안에만** 저장됩니다. 서버로 보내는 요청이 없습니다.
  - 프로젝트(글자 데이터): `localStorage`의 `toyz-frame:project`(스키마 버전 필드 포함). UI 설정은 `toyz-frame:ui`.
  - 이미지: IndexedDB `toyz-frame` 데이터베이스의 `images` 저장소.
- 저장값이 손상되면 앱은 예시로 시작하고, 원문은 `toyz-frame:project-corrupt-backup`에 보관합니다. 보관본이 있는 동안에는 손상된 프로젝트가 쓰던 이미지를 지우지 않습니다. **설정 → 손상된 저장본**에서 원문을 내려받거나, 남은 이미지를 "되살린 이미지" 작업으로 모으거나, 보관본을 지울 수 있습니다.
- 어디에서도 쓰지 않는 이미지(삭제 뒤 되돌리기 기간이 지난 것)는 다음 실행 때 정리합니다.
- 같은 브라우저에서 Frame을 여러 탭으로 열면, 한 탭이 저장한 내용을 다른 탭이 받아 와 맞춥니다. 바뀐 것이 없는 탭은 닫힐 때 저장하지 않아 다른 탭의 최신 내용을 덮어쓰지 않습니다.
- 브라우저 저장 공간이 가득 차면 이미지를 넣지 않고 안내합니다. IndexedDB를 쓸 수 없는 환경(일부 사생활 보호 모드)에서는 이미지가 탭을 닫을 때까지만 남으니 프로젝트 파일로 저장하라고 알려 줍니다.

## 내보낸 파일의 안전성

- 사용자가 입력한 글자는 모두 이스케이프하고, 링크는 `http(s)`, `mailto`, `tel`만 허용합니다. 색은 `#rrggbb` 형식만, 이미지 src는 `data:image/…`와 `blob:`만 통과시킵니다.
- 프로젝트 파일을 불러올 때 이미지마다 실제로 해석되는지 확인하고, 깨졌거나 이미지가 아닌 데이터는 빼고 알려 줍니다.
- 고른 포인트 색이 배경과 대비가 부족하면(예: 밝은 배경의 라임·주황), 작은 글자와 포커스 표시에는 같은 색 계열을 진하게(어두운 톤에서는 밝게) 조정한 색을 써서 WCAG AA(4.5:1)를 지킵니다. 장식과 배경에는 고른 색을 그대로 씁니다.
- 내보낸 문서에는 CSP 메타 태그가 들어 있습니다: 스크립트는 고정된 인라인 스크립트 하나만 **SHA-256 해시로** 허용하고, 이미지는 data:·blob:만, 그 밖의 모든 외부 요청(폰트·스타일시트·fetch)을 막습니다. 이스케이프가 뚫리더라도 삽입된 스크립트는 실행되지 않습니다. 인라인 스크립트를 고치면 `npm run test:unit`이 해시 불일치를 알려 줍니다.

## 알려진 한계

- 좁은 편집기(모바일)의 작업 목록에서는 제목을 읽을 수 있도록 삭제 버튼을 숨깁니다. 삭제는 작업 편집 화면 아래에서 할 수 있습니다.
- 움직이는 GIF는 첫 프레임만 남습니다(Canvas로 줄여 저장하기 때문).
- 내보낸 HTML은 웹폰트를 넣지 않고 시스템 서체를 씁니다. 특히 세리프·모노 제목은 보는 기기에 설치된 서체에 따라 모양이 조금 달라집니다.
- `og:image`는 넣지 않습니다. 공유 미리보기 이미지는 공개 URL이 있어야 하는데, 파일 하나로 완결되는 원칙과 맞지 않기 때문입니다.
- 이미지가 많으면 파일이 수십 MB가 될 수 있습니다. 20MB를 넘으면 내보내기 화면에서 알려 줍니다.
