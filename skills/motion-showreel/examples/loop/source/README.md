# LOOP — 혼자 시작해서 함께 완성하는 루틴

하루가 고리처럼 이어지는 습관 앱입니다. 작은 루틴을 매일 체크하고, 서버 없이 **초대 링크와 체크인 카드**를 주고받으며 크루와 함께 이어 갑니다.

toyz 마켓플레이스의 예시 프로젝트를 실제 앱으로 구현했습니다. 마켓플레이스에는 "작은 습관을 함께 이어 가는 커뮤니티 앱"이라는 소개만 있었고, 이 저장소는 그 소개를 브라우저 안에서 완결되는 실제 웹앱으로 만든 결과입니다.

## 주요 기능

**오늘**
- 오늘 할 루틴 목록과 한 번 탭 체크인. 횟수형 루틴(예: 물 8잔)은 링을 눌러 하나씩 채우거나 더하기·빼기로 고칩니다.
- 체크인마다 한 줄 메모를 남길 수 있습니다.
- '어제'로 바꾸면 어제 기록을 뒤늦게 남길 수 있고, 스트릭에도 바로 반영됩니다.
- 크롬 링으로 하루 달성률을 보여 주고, 마지막 고리를 채우면 절제된 축하 모션(링 광택 한 바퀴)과 알림이 나옵니다. `prefers-reduced-motion`을 켜면 모션을 줄입니다.
- 이번 주 요일별 진행, 크루 현황, 최근 응원을 한눈에 봅니다.

**루틴**
- 이름, 직접 그린 SVG 기호 20종, 색 10종, 주기(매일 · 요일 선택 · 주 N회), 하루 목표(한 번 · 횟수와 단위), 시작일, 메모.
- 템플릿 모음 12종에서 골라 빠르게 시작할 수 있습니다.
- 보관하면 오늘 목록에서 빠지고 지난 기록과 스트릭은 그대로 남습니다. 나중에 다시 꺼내도 보관해 둔 기간은 '해당 없는 날'로 남아, 그동안이 놓친 날로 바뀌어 스트릭이나 달성률이 깎이지 않습니다. 삭제는 확인 후 되돌리기 알림을 띄웁니다.

**기록**
- 루틴별 현재·최장 스트릭. 주기 규칙을 반영해 해당 없는 날(요일이 아닌 날, 시작일 이전, 쉬어간 날)은 끊기지 않습니다. 주 N회 루틴은 주 단위로 세고, 주의 마지막 날(일요일)이라도 오늘 한 번 더 하면 채울 수 있는 동안에는 끊지 않습니다.
- 최근 16주 히트맵, 월 달력(날짜를 누르면 그날의 루틴과 메모), 주간(8주)·월간(6개월) 달성률, 요일별 경향(12주).
- 전체 또는 루틴 하나만 골라 볼 수 있습니다.

**쉬어가기**
- 한 달에 두 번까지 쓸 수 있고, 쉬어간 날은 모든 루틴이 면제되어 스트릭이 유지됩니다. 주 N회 루틴에서는 1회로 인정합니다. 다음 달이 되면 다시 두 번이 채워집니다.

**함께(서버 없이)**
- **크루 만들기와 초대 링크**: 크루 이름과 함께할 루틴 묶음을 정하면 초대 링크가 생깁니다. 링크 안에 크루와 루틴 템플릿이 인코딩되어 있어, 받은 사람이 열면 미리 보고 '같이 시작하기'로 같은 루틴을 바로 시작합니다.
- **체크인 카드**: 내 이번 주 진행 스냅샷을 링크나 파일(.json)로 보냅니다. 받은 사람이 가져오면 크루 보드의 그 사람 칸이 갱신됩니다. 같은 사람의 카드는 최신 것으로 교체되고, 같은 카드를 다시 가져오거나 예전 카드를 늦게 열면 반영하지 않습니다.
- **크루 보드**: 멤버별 이번 주 달성률, 최고 스트릭, 요일별 링, 루틴별 진행을 나란히 봅니다. 내 칸은 내 기록으로 실시간 계산합니다.
- **응원**: 멤버 카드에서 응원 한마디를 적으면 응원 링크가 생깁니다. 받는 사람이 열면 응원함에 쌓이고, 같은 응원은 한 번만 들어갑니다.
- **첫 실행 예시 크루** '새벽 루프'와 가상의 크루원 3명(하늘·도윤·서아)이 '예시' 표시와 함께 들어 있습니다. 설정에서 지울 수 있습니다. 받은 링크로 처음 들어온 사람에게는 예시를 넣지 않습니다. 예시 크루는 체험용이라 초대·카드·응원 링크를 보내지 않고 '새 크루 만들기'로 안내합니다(예시 크루 id 는 모든 기기에서 같아서, 보내면 받는 사람의 예시 크루와 섞이기 때문입니다). 같은 이유로 예시 루틴은 실제 크루에 넣을 수 없고, 같은 루틴은 템플릿 모음에서 새로 고릅니다.
- **이번 주 요약 PNG 카드**: Canvas로 1080×1350 이미지를 그려 저장하거나(모바일에서는) 공유합니다.

**주간 회고**
- 잘된 점, 아쉬운 점, 다음 주 한 가지를 주별로 저장하고 보관함에서 다시 엽니다.

**데이터**
- JSON 내보내기·가져오기, 예시 데이터 지우기, 전체 초기화.
- 가져오기는 기록을 통째로 바꾸므로, 지금 기록과 파일의 기록(루틴·체크인·크루·회고·응원 수)을 나란히 보여 주고 확인을 받습니다. 빈 파일이면 따로 경고하고, 바꾼 직후에는 알림의 '되돌리기'로 되돌릴 수 있습니다.
- 여러 탭에서 열어 두어도 한 탭의 기록이 다른 탭에 곧바로 반영되어, 오래된 탭이 새 기록을 덮어쓰지 않습니다(받은 링크는 보통 새 탭에서 열리기 때문입니다).

**있으면 좋은 기능**
- 알림 시간(Notification API): 정한 시각이 지나도 오늘 남은 루틴이 있으면 하루 한 번 알립니다.
- 루틴 템플릿 모음: 새 루틴 화면과 크루 만들기에서 씁니다.

## 사용 방법

1. 첫 화면(오늘)에서 동그란 버튼을 눌러 체크인합니다. 횟수형은 링을 누르거나 더하기·빼기를 씁니다.
2. 어제 깜빡했다면 오른쪽 위 '어제'로 바꿔 체크합니다. 도저히 못 한 날은 '쉬어가기'를 씁니다(월 2회).
3. '함께'에서 이름을 정하고 크루를 만든 뒤 '초대 링크'를 메신저로 보냅니다.
4. 주말쯤 크루 보드에서 '내 체크인 카드 보내기'로 카드를 보내고, 받은 카드는 링크를 열거나 '링크·파일 가져오기'로 반영합니다.
5. 일요일 밤에는 '회고'에 세 줄을 남깁니다.

## 실행·빌드·테스트

Node 20.19 이상이 필요합니다.

```sh
npm install --no-audit --no-fund
npm run dev            # 개발 서버
npm run build          # 타입 검사 + 프로덕션 빌드(dist/)
npm run lint           # oxlint
npm run test:domain    # 도메인 순수 함수 자체 점검(node:test, 36건)
PORT=4314 npm run test:smoke   # 빌드 결과를 띄워 헤드리스 Chrome으로 실제 사용자 흐름 19개 시나리오 확인
```

- 스모크 테스트는 `?today=YYYY-MM-DD`로 날짜를 주입해 언제 실행해도 같은 결과가 나옵니다. 두 개의 브라우저 컨텍스트로 초대 → 같이 시작하기 → 체크인 카드(링크·파일) → 응원 왕복을 확인하고, 변조·잘린 링크 거부, 손상된 저장 데이터 복구도 확인합니다. 여러 탭 동시 사용, 가져오기 확인·되돌리기, 보관했다 꺼내기, 키보드만으로 크루 만들기, 모바일 주요 화면의 44px 터치 대상도 확인합니다.
- 서머타임이 있는 시간대에서도 날짜 계산이 맞는지 보려면 `TZ=America/New_York npm run test:domain`처럼 실행합니다.
- 디자인 점검용 스크린샷: `PORT=4314 node tests/shots.mjs 접두사` (대화상자·받은 링크 화면은 `FLOWS=1`을 붙입니다). 결과는 `tests/artifacts/`에 남습니다.

### 날짜 주입(테스트용)

주소 끝에 `?today=2026-09-21`을 붙여 열면 앱이 그 날을 오늘로 봅니다. 설정의 '테스트용 날짜'에서도 바꾸거나 해제할 수 있고, 주입 중에는 상단 띠에 '테스트 날짜' 표시가 붙습니다. 공유 링크에는 이 값이 들어가지 않습니다.

## 기술 구성

- Vite 8 + React 19 + TypeScript 6(strict), oxlint, playwright-core(스모크 테스트)
- 추가 런타임 의존성 없음. 폰트는 템플릿에 포함된 Pretendard Variable 자체 호스팅.
- 해시 라우팅(`#/today`, `#/crew/…`, `#/invite/…`)이라 서버 rewrite 설정이 필요 없습니다.
- 구조
  - `src/domain/` 순수 함수: 날짜(로컬 날짜 성분 기준, 서머타임 안전), 주기 판정, 스트릭·달성률·히트맵, 쉬어가기, 링크 인코딩·검증, 크루 반영, 예시 데이터
  - `src/state/` 작은 외부 스토어(`useSyncExternalStore`), 저장·복구, 동작 함수, 알림
  - `src/components/`, `src/screens/` 화면
  - `src/lib/` 라우터, 공유·저장, Canvas 요약 카드, 조사 처리
- 초기 JS는 gzip 약 112KB입니다.

### 링크 형식

초대·체크인 카드·응원 링크는 `#/invite/<토큰>`, `#/checkin/<토큰>`, `#/cheer/<토큰>` 모양입니다. 토큰은 JSON → UTF-8 → base64url이고, 끝에 FNV-1a 검사값을 붙입니다. 열 때는 검사값을 확인한 뒤 필드마다 형식·길이·범위를 엄격하게 검증하고 알려진 필드만 골라 씁니다. 손상되거나 바뀐 링크는 오류 화면에서 이유와 함께 거부하고, 무엇이든 반영하기 전에 먼저 미리보기를 보여 줍니다.

## 데이터 저장 방식과 개인정보

- 모든 기록은 이 기기 브라우저의 `localStorage`(`toyz-loop:state`, 스키마 버전 1)에만 저장됩니다. 서버, 계정, 분석 도구, 외부 네트워크 호출이 없습니다.
- 저장된 데이터가 손상되어도 필드마다 검증해 온전한 부분만 살려 다시 조립합니다. JSON 자체가 깨져 읽을 수 없으면 원문을 `toyz-loop:unreadable-backup`에 남겨 두고 빈 상태로 시작하며, 그 사실을 알림으로 알려 드립니다. 남겨 둔 원문은 설정 > 데이터에서 내려받거나 지울 수 있습니다.
- 저장 공간이 부족하거나 브라우저가 저장을 막으면 알림으로 알려 드립니다(새로고침하면 그동안의 기록이 사라질 수 있으니 JSON으로 내보내 두세요).
- 링크를 보내면 그 링크에 담긴 내용(크루 이름, 루틴 이름, 이번 주 달성률, 표시 이름, 응원 문구)이 받는 사람에게 그대로 전달됩니다. 메모와 회고는 링크에 들어가지 않습니다.
- 크루 보드에서 같은 사람을 알아보는 데 기기마다 무작위로 만든 id를 씁니다.

## 알려진 한계

- 서버가 없으므로 크루원의 진행은 체크인 카드를 주고받을 때만 갱신됩니다. 실시간 동기화는 없습니다. 초대받은 사람이 합류해도, 그 사람이 카드를 보내기 전까지는 초대한 쪽 보드에 나타나지 않습니다.
- 링크 검사값(FNV-1a)은 깨지거나 손으로 고친 링크를 거르는 용도이며 암호학적 서명이 아닙니다. 검사값까지 다시 계산한 링크는 막지 못하지만, 내용 검증으로 이상한 값이 앱에 들어오지는 않습니다.
- 브라우저 데이터를 지우면 새 사람(새 id)이 됩니다. 기기를 옮길 때는 JSON으로 내보내 가져와 주세요.
- 알림은 서비스 워커 없이 동작하므로 LOOP 탭이 열려 있을 때만 울립니다.
- 뒤늦은 기록은 어제까지만 남길 수 있습니다. 그 이전 날은 기록 화면에서 보기만 합니다.
- 루틴의 주기를 바꾸면 지난 기록도 새 주기로 다시 계산됩니다.
- 체크인 카드에서 쉬어간 날은 그날 달성으로 표시됩니다. 한 주의 시작은 월요일로 고정입니다.
- 사람 이름과 크루 이름은 40자, 응원은 300자, 카드 한 장의 루틴은 40개까지입니다.
