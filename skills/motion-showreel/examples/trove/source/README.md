# Trove — 흩어진 링크를 하나의 지식으로

Trove는 웹에서 모은 링크와 메모를 주제별로 모으는 개인용 북마크 도구입니다.
자동 태그 제안과 요약, 관련 링크 추천으로 저장해 둔 링크를 다시 찾는 시간을 줄여 줍니다.
검정 바탕에 크롬 은색과 라임 포인트를 쓴 어두운 화면이고, 밝은 테마로도 바꿀 수 있습니다.

> toyz 마켓플레이스의 예시 프로젝트를 실제 앱으로 구현했습니다. (toyz 토이 프로젝트 · Play Objects)

## 주요 기능

- **링크 추가**: 주소, 제목, 메모, 주제, 태그를 넣습니다. 주소만 넣어도 도메인과 경로로 제목 초안을 만들고 도메인 이니셜 아바타를 그립니다.
- **유효성 검사와 중복 감지**: http·https 주소만 받습니다. 스킴, `www.`, 끝 슬래시, `utm_*`·`fbclid` 같은 추적 파라미터, 파라미터 순서를 정규화해 비교하므로 표기가 달라도 같은 주소면 막고 기존 링크로 안내합니다.
- **여러 줄 붙여넣기**: 메모, 메신저 대화, 마크다운 목록을 붙여넣으면 URL을 모두 찾아 미리 보여 주고 새 링크만 한 번에 추가합니다. URL 앞의 글은 제목, 뒤의 글은 메모가 되고, `[제목](주소)` 형식도 읽습니다. `https://…/learn에서 봤어요`처럼 주소 바로 뒤에 붙은 조사는 주소에서 떼어 냅니다.
- **자동 태그 제안**: 제목과 메모에서 한국어·영어 키워드를 뽑습니다. 조사·어미를 떼고(받침 규칙에 맞는 조사만 떼어 `넘파이`·`전문가` 같은 낱말 끝을 지킵니다) 불용어와 용언 활용형을 거른 뒤 빈도와 위치로 점수를 매기고, 도메인 규칙(예: github.com → 개발, youtube.com → 영상)을 더합니다. 제안 칩을 누르면 태그로 확정됩니다.
- **자동 요약**: 메모가 세 문장 이상이면 문장마다 점수(다른 문장과 겹치는 낱말, 제목과 겹치는 낱말, 첫 문장 우대)를 매겨 핵심 한두 문장을 카드와 상세에 보여 줍니다.
- **보드와 목록**: 주제별 열로 보는 보드 보기와 정보가 촘촘한 목록 보기를 오갑니다. 보드에서는 카드를 다른 주제 열로 끌어다 놓아 옮길 수 있습니다.
- **필터·정렬·검색**: 여러 태그를 모두 포함하는 필터, 읽음/안 읽음, 핀 고정만 보기, 최신순·이름순·자주 연 순 정렬(핀 고정이 항상 먼저)을 씁니다. `/` 키로 검색창에 들어가 제목·메모·태그·도메인을 한꺼번에 찾고, 일치한 부분을 강조합니다.
- **상세 패널과 관련 링크**: 태그·키워드·도메인·주제로 만든 특징 벡터의 코사인 유사도로 관련 링크 3~5개를 추천하고, 왜 이어졌는지(공통 태그 등) 함께 보여 줍니다.
- **열람 기록**: 링크를 새 탭(`rel="noopener noreferrer"`)으로 열면 열람 횟수와 마지막 열람 시각을 기록합니다.
- **수정·삭제·주제 관리**: 수정, 삭제(되돌리기 알림), 주제 만들기·이름·색·순서 바꾸기·지우기(되돌리기 알림), 주제 간 이동을 지원합니다.
- **빠른 추가 주소**: `#/add?url=주소&title=제목` 으로 들어오면 추가 창이 미리 채워집니다. 보관함 관리 창에 이 주소를 여는 북마클릿이 있습니다.
- **내보내기·가져오기**: Trove JSON과 브라우저 북마크 HTML(Netscape 형식)을 양방향으로 지원합니다. 주제는 폴더가 되고, 가져올 때는 첫 폴더가 주제, 더 깊은 폴더 이름은 태그가 됩니다. 이름이 대소문자만 다른 폴더는 한 주제로 모읍니다. 30MB가 넘는 파일이나 브라우저 저장 공간에 다 들어가지 않는 가져오기는 기존 데이터를 건드리지 않고 거절합니다.
- **요약 영역**: 전체, 안 읽음, 이번 주 추가 수, 열람 합계, 주제별 분포, 자주 쓰는 태그를 첫 화면에 보여 줍니다. 분포 항목이나 태그를 누르면 바로 걸러집니다.
- **그 밖에**: J·K 키보드 탐색, 밝은 테마, 예시 데이터 지우기·넣기, 전체 초기화(되돌리기 가능), 다른 탭과의 저장 동기화.

## 사용 방법

1. 처음 열면 예시 링크 15개가 들어 있습니다. 보관함 관리(상단 슬라이더 아이콘)에서 언제든 지울 수 있습니다.
2. **링크 추가**(또는 `N` 키)를 눌러 주소를 붙여넣습니다. 제목 초안과 태그 제안을 확인하고 저장합니다. 휴대폰 폭에서는 엄지가 닿는 오른쪽 아래의 **+** 버튼을 씁니다.
3. 여러 개를 한꺼번에 넣으려면 추가 창의 **여러 개 붙여넣기** 탭을 씁니다.
4. 카드를 누르면 상세 패널이 열립니다. **새 탭에서 열기**로 링크를 열고, 읽음·핀·수정·삭제·주제 이동을 할 수 있습니다.
5. 다른 페이지에서 바로 저장하려면 보관함 관리의 **Trove에 추가** 버튼을 북마크바로 끌어다 놓습니다.

| 단축키 | 동작 |
| --- | --- |
| `/` | 검색창으로 이동 |
| `N` | 링크 추가 |
| `J` / `K` | 다음·이전 링크로 이동 |
| `Enter` | 선택한 링크의 상세 열기 |
| `O` | 선택한 링크를 새 탭에서 열기 |
| `Esc` | 검색어 지우기, 패널·창 닫기 |

## 실행·빌드·테스트

Node.js 20.19 이상이 필요합니다.

```sh
npm install --no-audit --no-fund
npm run dev            # 개발 서버
npm run build          # 타입 검사 + 프로덕션 빌드(dist/)
npm run lint           # oxlint
npm run test:unit      # 도메인 로직 단위 테스트(URL 정규화, 키워드, 요약, 북마크 HTML 등)
PORT=4301 npm run test:smoke   # 빌드본을 띄우고 헤드리스 Chrome으로 사용자 흐름 28단계를 확인
```

스모크 테스트는 설치된 Chrome을 `playwright-core`의 `channel: 'chrome'` 헤드리스 방식으로 씁니다. 링크를 새 탭으로 여는 단계에서도 바깥 사이트에 실제로 접속하지 않도록 앱 밖 요청은 빈 페이지로 대신 응답합니다.
`tests/shots.mjs`는 디자인 점검용 스크린샷을 `tests/artifacts/`에 남기는 보조 스크립트입니다.

## 기술 구성

- Vite 8, React 19, TypeScript 6(strict), oxlint, playwright-core
- 본문 서체 Pretendard Variable(자체 호스팅), 보조 라벨은 시스템 모노스페이스
- 외부 네트워크 호출, 백엔드, API 키가 없습니다. 크롬 토러스 그림도 이미지 파일 없이 코드로 계산합니다. 원 480개를 캔버스에 한 번 칠해 이미지로 캐시하고, 캔버스를 쓸 수 없는 환경에서만 인라인 SVG로 그립니다.

```text
src/
  domain/      순수 함수: URL 정규화·추출, 키워드·태그 제안, 요약, 검색·강조, 필터·정렬, 통계,
               관련 링크, 북마크 HTML 읽기·쓰기, JSON 가져오기·병합, 저장소 방어, 해시 라우트
  state/       리듀서(순수), 저장 훅, 해시 라우팅 훅, 컨텍스트
  components/  화면 조각(보드, 목록, 카드, 상세 패널, 추가 창, 주제 관리, 보관함 관리, 알림 등)
  lib/         요약 캐시, 발췌, 파일 내려받기, 토러스 도형 계산·캔버스 렌더, 모달 층 관리
tests/
  unit.mjs     도메인 단위 테스트
  smoke.mjs    사용자 흐름 스모크 테스트
```

## 데이터 저장 방식과 개인정보

- 모든 데이터는 이 브라우저의 `localStorage`에만 저장합니다. 키는 `toyz-trove:store`이고 `version` 필드로 스키마 버전을 둡니다.
- 서버로 아무것도 보내지 않고, 링크 페이지를 대신 열어 보지도 않습니다. 링크는 사용자가 누를 때만 새 탭에서 열립니다.
- 저장된 데이터가 손상되어 읽을 수 없으면 원본을 `toyz-trove:backup`에 그대로 보관하고 빈 보관함으로 시작합니다. 개별 항목이 잘못되어 있으면 그 항목만 건너뜁니다.
- 브라우저 데이터를 지우면 링크도 사라지므로, 중요한 목록은 JSON이나 북마크 HTML로 내보내 두세요.

## 알려진 한계

- 링크 페이지의 실제 제목·본문을 가져오지 않습니다(외부 호출이 없기 때문입니다). 제목 초안은 주소만으로 만듭니다.
- 키워드 추출과 요약은 형태소 분석기 없이 규칙으로 동작합니다. 드물게 용언 활용형이 제안에 섞이거나 요약 문장이 기대와 다를 수 있습니다.
- `localStorage` 용량(보통 5MB 안팎) 안에서만 저장할 수 있어, 수천 개 수준을 넘는 대량 보관에는 맞지 않습니다. 저장에 실패하면 알림으로 알려 줍니다.
- 북마크 HTML을 가져올 때 두 번째 단계보다 깊은 폴더 구조는 태그로 평탄화되고, 비어 있는 폴더는 주제로 만들지 않습니다. 가져온 링크는 모두 ‘안 읽음’으로 들어옵니다.
- 카드 끌어다 놓기는 마우스 기준입니다. 키보드와 터치에서는 상세 패널의 주제 선택으로 옮깁니다.
- 기기 간 동기화는 없습니다(같은 브라우저의 다른 탭끼리는 저장 내용을 따라갑니다).
- 관련 링크는 태그·키워드·도메인·주제가 하나라도 겹치는 링크만 추천하므로, 이어진 링크가 적으면 3개보다 적게 나올 수 있습니다.
- 사이트 파비콘 대신 도메인 이니셜 아바타를 씁니다.
- 한글 도메인(예: `한국.kr`)은 브라우저 주소 표준에 따라 `xn--…` 형태로 저장·표시됩니다.
- 저장 공간이 가득 차면 20초마다 저장 실패 알림을 다시 띄웁니다. 이때는 내보내기로 백업한 뒤 오래된 링크를 정리해 주세요.

## 출처

toyz 마켓플레이스의 예시 프로젝트를 실제 앱으로 구현했습니다. 예시 데이터 속 인물·상호·서비스 이름은 모두 가상입니다. 도메인 규칙을 보여 주려고 github.com처럼 실제 플랫폼 도메인을 쓴 항목이 하나 있지만, 그 안의 저장소와 글은 가상입니다.
