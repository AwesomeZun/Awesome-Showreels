# PIXEL KIT

> 작은 브랜드를 위한 이미지 제작 도구 — 브랜드 킷을 한 번 정하면 어떤 크기의 이미지도 같은 얼굴로 나옵니다.

toyz 마켓플레이스의 예시 프로젝트를 실제 앱으로 구현했습니다.

PIXEL KIT은 브랜드 색·서체·로고를 "킷"으로 저장해 두고, 13가지 템플릿을 인스타그램 피드·스토리·링크 카드·영상 썸네일·가로 배너 같은 여러 크기로 한 번에 만들어 내보내는 브라우저 도구입니다. 서버와 계정 없이 브라우저 안에서만 동작합니다.

## 주요 기능

- **브랜드 킷**: 브랜드 이름·슬로건, 색 3~5개와 역할(주색·보조색·강조색·배경·글자색), 역할 맞바꾸기, 대비 검사와 경고, 제목·본문 서체 조합(번들 서체 Pretendard·고운바탕, 시스템 서체 3종), 제목 굵기·자간, 로고(이미지 업로드 또는 이니셜 마크 자동 생성, 모양 4종, 이름 함께 쓰기). 킷 여러 개 저장·복제·삭제(되돌리기)·전환. 가상의 예시 킷 3개(모래알 베이커리, 숨결 요가 스튜디오, PADO Coffee Roasters).
- **크기 프리셋**: 정사각 1080×1080, 세로 1080×1350, 스토리 1080×1920, 링크 카드 1200×630, 영상 썸네일 1280×720, 가로 배너 1500×500, 사용자 지정(64~4096px).
- **템플릿 13종**: 타이포 포스터, 사진 오버레이, 분할 레이아웃, 메시 그라디언트, 기하 패턴, 인용문, 공지, 세일·이벤트, 신제품, 팁 카드, 후기, 일정 안내, 브랜드 카드. 모든 템플릿은 `(ctx, 크기, 브랜드, 내용)`을 받는 렌더 함수로, 세로·정사각·가로·초가로 비율에 맞춰 배치를 스스로 바꿉니다.
- **편집**: 템플릿별 글자 칸, 한글 어절 단위 자동 줄바꿈과 글자 크기 자동 맞춤(균형 줄바꿈 포함), 정렬, `{브랜드}`·`{슬로건}` 토큰, 로고 위치, 사진 업로드·위치·확대·필터(흑백·브랜드색 듀오톤·어둡게), 색 역할 조합 고르기·섞기, 배경 생성기(단색·선형 각도·원형·메시·패턴 8종과 밀도·노이즈 그레인·시드 새로 생성), 글자 요소 미세 위치 조정, 템플릿 즐겨찾기.
- **실시간 미리보기와 일관성 보기**: 캔버스로 축소해 바로 그리고, 같은 내용을 여섯 크기로 한 화면에 나란히 보여 줍니다.
- **대비 자동 검사**: 글자를 뺀 배경을 실제로 그려 각 글자 줄 뒤의 픽셀을 모은 뒤, 가장 나쁜 5% 지점과 글자색의 대비를 WCAG 기준(큰 글자 3:1, 일반 4.5:1)과 비교해 경고합니다. "대비 좋은 조합으로" 버튼이 킷 안에서 더 나은 색 조합(사진이면 어둡게 필터)을 찾아 적용합니다.
- **내보내기**: PNG·JPEG(품질)·WebP, 1x·2x, 파일 이름 규칙(`{brand}_{template}_{size}_{w}x{h}` 등), 여러 크기를 고르면 ZIP 하나로. 서체 조각과 이미지를 모두 불러온 뒤(`document.fonts.load` → `document.fonts.ready`) 원본 해상도로 다시 그립니다.
- **보관함**: 썸네일과 함께 저장, 이어서 편집, 사본으로 저장, 복제, 삭제(되돌리기), 전체·개별 JSON 내보내기와 가져오기(올린 사진·로고 포함). 가져올 파일이 지금 있는 킷·디자인을 다른 내용으로 덮어쓰게 되면 먼저 묻습니다.
- **설정**: 저장 공간 확인, 쓰지 않는 이미지 정리, 예시 데이터 지우기, 전체 초기화.

## 사용 방법

1. 처음 열면 예시 킷과 예시 디자인이 들어 있어 바로 만져 볼 수 있습니다.
2. 왼쪽에서 템플릿을 고르고, 캔버스 위에서 크기를 고른 뒤, 오른쪽 탭(내용·배치 / 사진 / 배경 / 색)에서 고칩니다. 화면이 좁으면 템플릿 목록은 오른쪽 탭의 "템플릿"으로 들어갑니다.
3. 상단의 킷 메뉴로 브랜드 킷을 바꾸면 모든 템플릿과 크기가 새 킷의 색·서체·로고로 바로 바뀝니다. "브랜드 킷" 화면에서 킷을 만들고 고칩니다.
4. "일관성 보기"에서 여섯 크기를 한눈에 확인하고, 고른 크기를 한 번에 내보냅니다.
5. "저장"(⌘/Ctrl + S)으로 보관함에 넣고, "내보내기"(⌘/Ctrl + E)로 파일을 받습니다.

## 실행·빌드·테스트

```sh
npm install --no-audit --no-fund
npm run dev            # 개발 서버
npm run build          # 타입 검사 + 프로덕션 빌드(dist/)
npm run lint           # oxlint
npm run test:unit      # 도메인 순수 함수 검증(node 22 타입 제거로 .ts를 직접 불러옵니다)
PORT=4316 npm run test:smoke   # 빌드본을 띄워 헤드리스 Chrome으로 사용자 흐름 39단계를 확인
```

스모크 테스트는 내보낸 PNG·JPEG·WebP 파일의 헤더를 직접 읽어 실제 픽셀 크기를 확인하고, ZIP을 풀어 파일 수·이름·크기를 확인합니다. 큰 사진(4000×3000) 업로드 축소, 저장·복제·삭제·되돌리기, 새로고침 뒤 유지, JSON 백업·복원, 킷 대비 경고와 자동 개선, 로고 이미지, 손상된 저장 데이터, 모바일 가로 넘침과 터치 크기도 확인합니다. QA에서 찾은 문제의 회귀 시나리오(예시 데이터를 지워도 저장 안 된 변경 유지, 긴 브랜드 이름 로고 넘침, 작은 SVG 로고 해상도, 가져오기 파일의 SVG 썸네일, 크기별 잘림 경고, 대화상자 위 단축키, 삭제 뒤 키보드 포커스, 편집 패널 전체의 44px 터치 대상, 모든 칸을 최대 길이로 채웠을 때 가격·버튼이 캔버스 밖으로 밀려나지 않음, 넘친 일정 행이 아랫글과 겹치지 않음, 여러 탭 동시 사용 시 킷 보존과 망가진 값 복구, 저장하는 동안 이어서 입력한 글자 보존, 사용자 지정 크기 빈 칸, ‘본문으로 건너뛰기’가 화면을 바꾸지 않음, 잘못 인코딩된 주소, 가져오기 덮어쓰기 확인)도 함께 돌립니다. 결과 스크린샷은 `tests/artifacts/`에 남습니다(저장소에는 넣지 않습니다).

`tests/lab/`은 개발용 도구입니다. 개발 서버에서 `/tests/lab/index.html?kit=0&t=quote`처럼 열면 템플릿을 모든 크기로 한꺼번에 그려 줍니다(빌드에는 포함되지 않습니다).

## 기술 구성

- Vite 8, React 19, TypeScript 6(strict), oxlint, playwright-core(테스트)
- Canvas 2D로 직접 렌더링합니다. 모든 템플릿은 논리 좌표(프리셋 픽셀)로 그리고, 캔버스 변환 배율만 바꿔 미리보기(축소)와 내보내기(원본·2배)를 같은 배치로 만듭니다.
- 의존성: `fflate`(ZIP, 내보낼 때만 불러옴), `pretendard`(자체 호스팅), `@fontsource/gowun-batang`(자체 호스팅 명조 1종)
- 구조
  - `src/domain/` 순수 함수: 글자 배치(`textLayout.ts`), 색·대비(`color.ts`), 킷 역할 규칙(`kits.ts`), 색 역할 조합(`schemes.ts`), 크기·파일 이름·검증
  - `src/render/` 렌더링 엔진(`engine.ts`), 템플릿 13종(`templates/`), 배경 생성기, 사진 필터, 대비 분석, 내보내기
  - `src/state/` 저장소(localStorage·IndexedDB), 동작, 예시 데이터, 해시 라우팅
  - `src/views/`, `src/components/` 화면

### 설계 메모

- 정보 구조: 스튜디오(`#/`) · 일관성 보기(`#/sizes`) · 브랜드 킷(`#/kits/:id`) · 보관함(`#/library`) · 설정(`#/settings`)
- 데이터 모델: `BrandKit { colors[역할], fonts, logo }`, `DesignDoc { templateId, sizeId, content, colorMap, background, photo, offsets }`, 저장본은 `SavedDesign = DesignDoc + thumb`. 템플릿의 색 자리(바탕·글자·포인트)는 킷의 색 역할에 연결(`colorMap`)되므로 킷을 바꾸거나 역할을 섞어도 배치는 그대로입니다.
- 한글 줄바꿈: 띄어쓰기(어절) 단위로 줄을 채우고, 한 어절이 한 줄보다 길 때만 최소 크기에서 글자 단위로 끊습니다. 크기는 상자에 들어가는 가장 큰 값을 이진 탐색으로 찾고, 제목은 줄 수를 유지한 채 폭을 줄여 줄 길이를 고르게 맞춥니다. 여러 칸이 세로로 쌓이는 템플릿은 칸마다 맞춘 높이의 합이 영역을 넘으면 칸들의 높이 한도를 비율대로 줄여 다시 맞추므로, 긴 글을 여러 칸에 넣어도 아래 칸(가격·버튼)이 캔버스 밖으로 밀려나지 않습니다. 목록·일정처럼 행이 있는 칸은 최소 크기에서도 넘치면 들어가는 행까지만 그립니다. 그래도 넘치면 말줄임하고 화면에 경고합니다.
- 서체: Pretendard와 고운바탕은 유니코드 범위별 조각 서체라서, 캔버스에 쓰기 전에 실제 글자로 `document.fonts.load()`를 불러 필요한 조각을 받습니다. 새 조각이 들어오면 측정 캐시를 비우고 다시 그립니다.

## 데이터 저장 방식과 개인정보

- 모든 데이터는 이 브라우저 안에만 저장되고 서버로 보내지 않습니다. 외부 네트워크 호출이 없습니다.
- `localStorage`(`toyz-pixel-kit:state`, 스키마 버전 포함): 브랜드 킷, 작업 중인 디자인, 내보내기 설정, 즐겨찾기
- IndexedDB(`toyz-pixel-kit`): 저장한 디자인과 썸네일(`designs`), 올린 사진·로고(`assets`)
- 사진은 올릴 때 긴 변 2400px(로고는 1024px)로 줄여 저장합니다. SVG는 벡터라서 아이콘 크기(예: 24×24)로 적혀 있어도 긴 변 2400px(로고 1024px)로 선명하게 다시 그려 저장합니다. 40MB가 넘는 파일은 받지 않습니다. 앱을 열 때 어디에서도 쓰지 않는 이미지는 정리합니다(방금 올린 이미지는 1분 동안 정리하지 않습니다).
- 저장된 데이터가 손상돼 있으면 따로 백업해 두고 초기 상태로 시작하며, 화면 위에 안내를 보여 줍니다.
- 같은 브라우저에서 PIXEL KIT을 여러 탭으로 열면, 한 탭에서 저장한 상태를 다른 탭이 곧바로 받아 씁니다(먼저 열어 둔 탭이 오래된 상태로 덮어쓰지 않습니다). 두 탭에서 같은 순간(0.25초 안)에 고치면 나중에 저장한 탭의 내용이 남습니다. 다른 탭이나 프로그램이 읽을 수 없는 값을 쓰면, 열려 있는 탭이 자기 상태로 다시 저장해 되살립니다.

## 알려진 한계

- 시스템 서체(시스템 고딕·명조·고정폭)는 보는 기기의 서체를 쓰므로 기기마다 모양이 다를 수 있습니다. 어디서나 같은 결과가 필요하면 번들 서체(Pretendard·고운바탕)를 고르세요.
- Safari 등 일부 브라우저는 캔버스를 WebP로 저장하지 못합니다. 이때 WebP 버튼은 꺼지고 이유를 알려 줍니다.
- 브라우저 캔버스 한도(가로×세로 16,777,216픽셀)를 넘는 크기는 2x 대신 1x로 저장하고 안내합니다.
- 캔버스 위에서 글자를 직접 끌어 옮기는 기능은 없고, 오른쪽 패널의 화살표로 0.5%씩 옮깁니다.
- 대비 검사는 글자 줄의 사각형 영역을 표본으로 삼는 근사치입니다. 경고가 없어도 작은 글자는 실제 크기로 한 번 더 확인해 주세요.
- 편집 되돌리기(⌘Z)는 입력 칸 안에서만 됩니다. 삭제는 알림의 "되돌리기"로 복구합니다.
