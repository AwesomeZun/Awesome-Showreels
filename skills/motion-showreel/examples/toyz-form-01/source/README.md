# FORM / 01

디자이너를 위한 가벼운 피드백 보드입니다. 작업물을 올리고, 같은 화면 위에 번호 핀과 영역을 찍어 피드백을 모읍니다.
버전을 쌓아 비교하고, 리포트·주석 이미지·보드 파일로 내보낼 수 있습니다. 서버도 로그인도 없이 브라우저 안에서 모두 동작합니다.

> toyz 마켓플레이스의 예시 프로젝트 **FORM / 01**("디자이너를 위한 가벼운 피드백 보드")을 실제 앱으로 구현했습니다.

콘셉트는 **정밀한 검수대**입니다. 작업물이 주인공이고 도구는 얇고 정확하게 둡니다. 도구 화면은 거의 검정과 금속 회색(#D9DADC → #8E9096)만 쓰고, 선명한 색은 리뷰어의 핀에만 씁니다. 첫 화면의 금속판에는 예시 목업 두 장을 재단선·치수선과 함께 올려, 이 앱이 무엇을 하는지 핀 모양 그대로 보여 줍니다.

## 주요 기능

- **보드와 프레임**: 보드 만들기·이름과 설명 바꾸기·삭제(되돌리기 가능). 보드 안에 작업물(프레임)을 여러 장 둡니다.
  - 이미지는 파일 선택, 화면에 끌어다 놓기, 클립보드 붙여넣기(⌘/Ctrl + V)로 올립니다. PNG, JPEG, WebP, SVG를 받습니다(한 장 24MB까지).
  - 원본은 IndexedDB에 Blob으로 저장하고, 목록용 썸네일(긴 변 480px JPEG)을 따로 만듭니다.
  - 첫 실행 때 절차적으로 그린 SVG 목업 3장(랜딩·대시보드·모바일 온보딩)과 세 리뷰어의 예시 코멘트가 든 보드가 들어 있습니다. 빈 보드에서는 "예시 목업 3장 넣기"로 바로 체험할 수 있습니다.
- **캔버스 뷰어**: 커서 기준 확대·축소(휠, Ctrl/⌘ + 휠, 트랙패드 핀치, 터치 핀치, + − 버튼), 이동(스페이스 + 드래그, 이동 도구, 두 손가락, 화살표 키), 화면 맞춤(0)과 100%(1). 모서리 재단선과 치수 표시가 붙은 작업대 위에 작업물을 올립니다. 데스크톱에서는 커서가 작업물 위에 있을 때 원본 픽셀 좌표(X·Y)를 확대 묶음 위에 보여 줍니다.
- **핀 코멘트**: 이미지의 정규화 좌표(0~1)에 번호 핀을 찍습니다. 작성자 이름과 색, 답글 스레드, 수정, 코멘트·답글 삭제(되돌리기), 상태(열림·해결됨), 라벨(레이아웃·타이포·색·카피·인터랙션·기타), 우선순위(낮음·보통·높음)를 둡니다.
  - 영역 코멘트: R 도구로 드래그해 사각형을 지정합니다.
  - 핀을 끌어서 위치를 옮길 수 있습니다(영역은 크기를 유지한 채 이동).
  - 본문의 `@이름` 언급을 강조합니다. 보드에 있는 리뷰어 이름이면 금속 배지로 표시합니다.
- **사이드 패널**: 번호순·최신순 정렬, 상태·라벨·작성자 필터(캔버스의 핀에도 함께 적용), 목록 ↔ 핀 상호 강조, 목록에서 고르면 그 위치로 캔버스 이동, 미해결 수 배지, 보드 해결률 추이 스파크라인.
- **버전**: 같은 프레임에 새 버전(v2, v3 …)을 올리고 칩으로 전환합니다. 비교 모드는 좌우 슬라이더와 겹쳐 보기(불투명도)를 지원합니다. "v1 핀 가져오기"로 이전 버전의 핀을 새 버전에 복사합니다(같은 핀은 두 번 가져오지 않습니다).
- **리뷰어 전환**: 이름과 핀 색을 바꿔 여러 사람 역할로 리뷰해 볼 수 있습니다. 최근 리뷰어 목록에서 바로 고를 수 있습니다.
- **내보내기·가져오기**
  - 피드백 리포트(.md): 상태 요약(현재 버전 기준), 라벨별 집계, 프레임 → 버전 → 라벨 순서의 코멘트와 답글. 본문에 든 HTML 태그는 `\<` `\>` 로 이스케이프해 마크다운 뷰어에서 태그로 해석되지 않습니다.
  - 주석 이미지(.png): 원본 해상도 그대로 캔버스에 합성합니다. 핀 모양·위치는 화면과 같은 좌표 변환을 씁니다.
  - 보드 파일(.form01.json): 이미지를 data URL로 담아 내보내고 가져옵니다. 같은 보드 id면 프레임·버전·코멘트를 id 기준으로 병합합니다. 읽을 수 없는 이미지가 섞여 있으면 그 버전만 빼고 나머지를 가져오며, 건너뛴 수를 알려 드립니다.
  - 같은 브라우저의 다른 탭과 BroadcastChannel로 실시간 동기화합니다.
- **모바일**: 탭으로 핀을 찍으면 하단 시트에서 코멘트를 씁니다. 찍은 자리가 올라온 시트에 가리지 않게 캔버스를 옮깁니다. 코멘트 목록·스레드·프레임 목록도 하단 시트로 엽니다. 터치 기기에서는 누를 수 있는 대상을 모두 44px 이상으로 두고, 버전이 많으면 버전 칩만 가로로 넘깁니다.
- **설정**: 예시 데이터 지우기(되돌리기), 예시 보드 다시 만들기, 전체 초기화(확인 절차), 단축키 안내. 보드가 하나도 없으면 첫 화면에서도 "예시 보드 불러오기"로 바로 예시를 만들 수 있습니다.
- **접근성**: 키보드만으로 보드 만들기 → 캔버스에서 Enter 로 핀 → ⌘/Ctrl + Enter 저장 → Tab 으로 해결까지 할 수 있습니다. 대화상자는 입력란에 포커스를 두고, 코멘트를 저장하거나 취소하면 포커스가 캔버스로 돌아옵니다. Tab 으로 화면 밖의 핀에 가면 캔버스가 그 핀이 보이게 움직입니다. 핀 번호 글자는 핀 색에 따라 흰색·검정 중 대비가 큰 쪽(WCAG AA 4.5:1 이상)을 씁니다.

## 사용 방법

1. 보드 목록에서 예시 보드를 열거나 **새 보드**를 만듭니다. 목록 화면에 이미지를 끌어다 놓아도 새 보드가 만들어집니다.
2. 작업물을 올립니다. 보드 화면에 파일을 끌어다 놓으면 "새 프레임"과 "지금 프레임의 새 버전" 중 하나를 고를 수 있습니다.
3. 캔버스를 눌러 핀을 찍고(C), 드래그해 영역을 지정하고(R), 코멘트를 남깁니다. ⌘/Ctrl + Enter로 저장합니다.
4. 오른쪽 패널에서 답글을 달고, 해결 처리하고, 라벨·우선순위를 바꿉니다.
5. 새 버전을 올려 비교하고, 남은 핀을 가져옵니다.
6. 오른쪽 위 **내보내기**에서 리포트·주석 이미지·보드 파일을 받습니다.

### 단축키

| 키 | 동작 |
| --- | --- |
| C / R / V | 핀 도구 / 영역 도구 / 이동 도구 |
| Space + 드래그 | 잠깐 이동 (마우스로 도구·확대 버튼을 누른 뒤에도 이동입니다. Tab 으로 버튼에 온 경우에는 스페이스가 버튼을 누릅니다) |
| 휠 · 핀치 · + − | 커서 기준 확대·축소 (Shift + 휠은 이동) |
| 1 / 0 | 100% / 화면 맞춤 |
| [ / ] | 이전 / 다음 프레임 |
| 화살표 | 캔버스 이동 (Shift와 함께 크게) |
| Enter | 캔버스에 포커스가 있을 때 보이는 영역 가운데에 핀 |
| Esc | 초안 취소 → 비교 닫기 → 시트 닫기 → 선택 해제 |
| ⌘/Ctrl + Enter | 코멘트·답글 저장 |
| ⌘/Ctrl + V | 클립보드 이미지를 새 프레임으로 |

## 실행·빌드·테스트

Node.js 20.19 이상이 필요합니다.

```sh
npm install --no-audit --no-fund
npm run dev            # 개발 서버
npm run build          # 타입 검사 + 프로덕션 빌드(dist/)
npm run lint           # oxlint
npm run test:domain    # 도메인 순수 함수 검증(좌표 왕복, 병합 멱등, 리포트, 추이 등)
npm run build && PORT=4313 npm run test:smoke   # 헤드리스 Chrome으로 실제 사용자 흐름 22개 확인
```

스모크 테스트는 `vite preview`를 띄우고 로컬에 설치된 Chrome을 헤드리스로 실행합니다. 주요 화면 스크린샷과 내려받은 파일은 `tests/artifacts/`에 남습니다(커밋하지 않습니다). 확인하는 흐름은 다음과 같습니다.

- 보드 만들기·이름 바꾸기·삭제와 되돌리기, 새로고침 뒤 유지
- 파일 선택·붙여넣기·드래그 앤 드롭 업로드
- SVG 속 스크립트·이벤트 속성이 실행되지 않고 저장본에서도 제거되는지
- 확대·스페이스 이동 뒤 찍은 핀의 정규화 좌표와 화면 위치(오차 1.5px 이내), 배율을 바꿔도 같은 점을 가리키는지
- 영역 코멘트, 핀 드래그, 답글·수정·라벨·해결·필터·정렬·삭제 되돌리기, 목록 선택 시 캔버스 이동
- 리뷰어 전환, 버전 추가·핀 가져오기(중복 없음)·슬라이더/겹쳐 보기 비교
- 단축키, 키보드만으로 코멘트 남기기
- 리포트 내용, 주석 PNG 해상도와 핀 위치 픽셀 색, 보드 파일 내보내기
- 다른 탭 실시간 반영, 빈 브라우저로 가져오기, 같은 파일 재가져오기 멱등, 다른 쪽 변경 병합
- 약 8MB 이미지 저장, 보드 파일 크기(원본의 약 1.34배), 원본 해상도 주석 PNG
- 모바일(390px) 가로 넘침 없음, 44px 터치 대상, 탭으로 핀 + 하단 시트, 두 손가락 핀치(중점 고정)·이동, 설정의 예시 데이터 지우기(되돌리기)·전체 초기화
- QA 회귀: 확대한 채 Tab 으로 핀에 포커스해도 뷰어가 스크롤되지 않고 이어서 찍은 핀 좌표가 정확한지, 도구·확대 버튼을 누른 뒤 스페이스+드래그가 이동인지, 대화상자 포커스, 삭제 되돌리기 뒤 핀 번호 중복 없음, 답글 삭제 되돌리기, 리포트의 HTML 이스케이프, 핀 번호 글자 대비, 모바일 초안 핀이 작성 시트에 가리지 않는지, 보드를 지운 직후 같은 파일을 가져와도 이미지가 남는지, 깨진 이미지가 섞인 보드 파일 가져오기

## 기술 구성

- Vite 8, React 19, TypeScript 6(strict), oxlint, playwright-core(스모크 테스트)
- 본문 서체는 자체 호스팅한 Pretendard Variable입니다. 외부 CDN·폰트 링크를 쓰지 않습니다.
- 추가 런타임 의존성은 없습니다. 확대·이동, 핀 합성, 병합, 리포트, 추이 차트는 모두 직접 구현했습니다.
- 빌드 결과에는 콘텐츠 보안 정책(CSP) 메타 태그를 넣습니다(`vite.config.ts`). 스크립트는 같은 출처에서만, 이미지는 같은 출처·blob·data에서만 읽습니다.

```text
src/
  domain/      순수 함수 — 타입, 좌표 변환, 코멘트·필터·핀 가져오기, 병합, 보드 파일 검증, 리포트, 집계·추이, 예시 데이터
  render/      주석 PNG 합성(Canvas)
  storage/     IndexedDB, localStorage 설정, 이미지 디코딩·SVG 정리·썸네일
  state/       전역 상태(useSyncExternalStore), 이미지 캐시, 내보내기 동작
  sync/        BroadcastChannel 탭 동기화
  hooks/       해시 라우팅, 미디어 쿼리
  components/  화면(Home, BoardView, Viewer, CommentPanel, FrameRail …)
  styles/      홈·보드 화면 스타일
tests/
  domain.test.mjs  도메인 검증(Node에서 .ts 를 바로 읽습니다)
  smoke.mjs        실제 사용자 흐름 스모크 테스트
```

### 좌표와 정확도

핀은 이미지 기준 정규화 좌표(0~1)로 저장합니다. 화면 좌표는 `screen = t + norm × 이미지 크기 × scale` 한 가지 식으로만 오가며(`src/domain/geometry.ts`), 뷰어·핀 드래그·주석 PNG가 모두 같은 함수를 씁니다. 이미지는 CSS `scale` 대신 실제 너비·높이로 배치해 SVG가 확대해도 선명하고, 핀은 화면 좌표에 고정 크기로 그립니다. 핀 말풍선의 왼쪽 아래 뾰족한 모서리가 정확히 그 점을 가리킵니다.

### 보드 파일과 병합 규칙

- 형식: `{ format: "toyz-form-01/board", schemaVersion, exportedAt, board, images: { [imageId]: { type, width, height, dataUrl } } }`
- 가져올 때 모든 값을 검사해 형식이 맞는 것만 남깁니다. 이미지는 실제 data URL 타입으로 다시 디코딩하고, SVG는 다시 정리합니다.
- 같은 보드 id가 있으면 병합합니다. 프레임·버전은 id로 합치고, 코멘트는 id 기준으로 `updatedAt`이 더 최근인 쪽을 남기며 답글은 id로 합칩니다. 같은 프레임에서 번호가 겹치면 나중에 만든 코멘트에 새 번호를 줍니다.
- 같은 파일을 몇 번 가져와도 결과가 같습니다(멱등). `tests/domain.test.mjs`와 스모크 테스트가 이를 확인합니다.

## 데이터 저장 방식과 개인정보

- 보드·프레임·코멘트는 IndexedDB `toyz-form-01`의 `boards` 저장소에, 이미지 원본과 썸네일은 `images` 저장소에 저장합니다.
- 현재 리뷰어와 최근 리뷰어 목록은 localStorage의 `toyz-form-01:` 접두사 키에 스키마 버전과 함께 저장합니다.
- 저장된 값이 손상되어도 앱이 멈추지 않도록 읽을 때마다 검증하고, 형식이 맞지 않는 항목은 건너뜁니다.
- 지운 보드·프레임·버전의 이미지는 되돌리기 시간(9초)이 지난 뒤, 그때도 어느 보드도 쓰지 않을 때만 지웁니다. 그 전에 탭을 닫아 남은 이미지는 다음에 앱을 열었을 때 30초 간격으로 두 번 확인해 정리합니다.
- 모든 데이터는 이 브라우저 안에만 있습니다. 서버로 보내는 요청이 없고, 분석 도구도 쓰지 않습니다. 다른 기기로 옮기려면 보드 파일로 내보내 주세요.
- 업로드한 SVG는 `<img>`로만 그려 안의 스크립트가 실행되지 않습니다. 저장할 때도 `<script>`, `on*` 속성, `javascript:` 링크, 링크·이벤트 속성을 바꾸는 `<animate>`·`<set>` 을 걷어 냅니다.

## 알려진 한계

- **탭 동기화는 같은 브라우저 안에서만** 됩니다(BroadcastChannel). 다른 기기와는 보드 파일로 주고받습니다. 두 탭에서 거의 동시에 같은 보드를 고치면 마지막에 저장한 탭의 내용이 남습니다.
- **보드 파일 병합은 삭제를 전파하지 않습니다.** 한쪽에서 지운 코멘트도 상대 파일에 남아 있으면 병합 때 다시 들어옵니다(삭제 기록을 따로 두지 않습니다).
- **트랙패드 판별은 추정입니다.** 가로 성분이 있는 연속 스크롤은 이동, 그 밖의 휠은 확대로 처리합니다. 세로로만 굴리는 트랙패드 스크롤은 확대로 동작할 수 있으니, 이동은 Shift + 휠이나 스페이스 + 드래그를 써 주세요.
- 한 장 24MB까지 올릴 수 있습니다. 주석 PNG는 긴 변 8192px, 넓이 3600만 픽셀을 넘으면 비율을 지킨 채 줄여서 만듭니다. 외부 리소스를 참조하는 SVG는 캔버스에 그릴 수 없어 주석 PNG를 만들지 못할 수 있습니다.
- 크기가 다른 버전을 비교하면 너비를 맞추고 위쪽을 기준으로 겹칩니다.
- 핀 번호는 프레임 단위로 이어서 매깁니다. 그래서 v2에서 새로 찍은 핀이 5번부터 시작할 수 있습니다. 이전 버전에서 가져온 핀과 답글은 복사본이라 원본과 따로 관리됩니다.
- "열림" 수와 해결률은 각 프레임의 **현재(최신) 버전** 기준으로 셉니다. 이전 버전의 코멘트는 리포트의 프레임별 목록에서 확인할 수 있습니다.
- 브라우저 저장 공간이 모자라면 저장이 실패할 수 있습니다. 이때는 알림으로 알려 드립니다.
