# Read Room

> 읽고 싶은 글을, 함께 읽을 사람과.

Read Room은 짧은 글 한 편을 펼쳐 놓고 여럿이 밑줄과 메모를 나누는 작은 온라인 읽기 모임 도구입니다.
서버 없이 브라우저 안에서만 동작하며, 공유 링크와 `.readroom.json` 파일을 주고받아 서로의 밑줄과 메모를 한 방에 쌓아 갑니다.

toyz 마켓플레이스의 예시 프로젝트를 실제 앱으로 구현했습니다.

## 주요 기능

- **서재(방 목록)**: 방마다 읽기 진행률, 밑줄·메모·질문 수, 모임 일시(D-day), 예상 읽기 시간을 보여 줍니다. 제목·출처·본문·참여자 이름으로 검색하고, 모임 가까운 순·최근 활동 순·제목 순으로 정렬합니다.
- **방 만들기·고치기·지우기**: 제목, 붙여 넣은 글, 출처 표기, 모임 일시, 내 참여자 프로필(이름과 색)을 적습니다. 글은 빈 줄 기준으로 문단을 나누고 간단한 마크다운(`#`·`##`·`###` 제목, `**굵게**`, `*기울임*`, `> 인용`, `---` 구분선)을 해석합니다. 오른쪽에서 실제 읽기 화면과 같은 조판으로 미리 봅니다. 지우기는 확인 후 되돌리기 알림을 띄웁니다.
- **읽기 화면**: 은빛 책상 위의 종이 한 장처럼 조판합니다. 본문 폭은 글자 크기에 맞춰 약 36자로 유지하고, 글자 크기(15~24px)·줄 간격(1.5~2.1)·테마(밝게·종이·어둡게)·서체(산세리프 Pretendard, 세리프 고운바탕)를 바꿀 수 있습니다. 머리 막대에 진행률과 한국어 기준 남은 읽기 시간을 보여 주고, 다시 들어오면 마지막으로 읽던 문단으로 돌아갑니다.
- **밑줄(하이라이트)**: 글을 끌어 선택하면(모바일은 길게 눌러 선택하면 아래 시트로) 4가지 색 중 하나로 바로 긋거나 메모와 함께 긋습니다. 굵게·기울임·다른 밑줄에 걸친 선택도 "문단 id + 평문 글자 오프셋"으로 정확히 저장합니다. 밑줄을 누르면 메모 보기·고치기, 색 바꾸기, 지우기(되돌리기)를 합니다. 겹친 밑줄은 짧은 것을 위에 칠하고 다른 색은 밑줄로 보여 주며, 누르면 겹친 밑줄을 모두 나열합니다.
- **문단 메모 스레드**: 넓은 화면에서는 문단 옆 여백에 카드로, 좁은 화면에서는 아래 시트로 메모와 답글을 나눕니다. 작성자 이름·색·시각이 함께 보이고, 고치기·지우기(되돌리기)를 할 수 있습니다.
- **토론 질문**: 질문을 올리고 관련 문단을 연결합니다. "다뤘어요"로 체크하고 전체·남은 질문·다룬 질문으로 거릅니다. 연결된 문단 칩을 누르면 그 문단으로 이동합니다.
- **함께 읽기(서버 없이)**
  - 공유 링크: 방 전체를 `CompressionStream('deflate-raw')`로 압축하고 base64url로 바꿔 URL 해시(`#/i/d.…`)에 담습니다. 8,000자를 넘으면 메신저에서 잘릴 수 있다고 경고하고, 32,000자를 넘으면 파일 공유를 강하게 권합니다. 잘린 링크를 열면 이유를 알려 줍니다.
  - 파일: `.readroom.json`으로 방을 내보내고 가져옵니다. 설정 화면에서는 전체 백업도 할 수 있습니다.
  - 병합: 같은 방 id면 항목(밑줄·메모·질문·공감) id 기준으로 합칩니다. 수정 시각이 최신인 쪽이 이기고, 같은 시각이면 결정적인 규칙으로 한쪽을 골라 어느 쪽에서 합쳐도 같은 결과가 됩니다. 삭제는 tombstone으로 전파되어 오래된 수정본이 지운 항목을 되살리지 못합니다. 가져오기 전에 "새로·수정·삭제" 요약을 보여 주고, 같은 파일을 두 번 가져와도 중복이 생기지 않습니다.
  - 탭 동기화: 같은 브라우저의 여러 탭은 `BroadcastChannel`로 실시간으로 맞춰집니다. 알림을 받은 탭은 저장소에서 다시 읽기만 하고 다시 알리지 않아 되돌이 루프가 없습니다. 쓰기 직전에는 저장소의 최신 값을 다시 읽어 서로의 변경을 덮어쓰지 않습니다.
- **모임 진행 모드**: 조용히 읽기·나눔·마무리 단계의 시간을 정하고 시작·일시정지·다음 단계·처음으로를 누릅니다. 남은 시간은 끝나는 시각 기준으로 계산해 탭이 뒤에 있어도 어긋나지 않습니다. 단계가 끝나면 Web Audio로 합성한 종소리가 울리고 알림이 뜹니다. 타이머는 앱 최상위에서 돌기 때문에 서재나 설정 화면으로 나가 있어도 알림음이 울리고, 알림의 "방 열기"로 바로 돌아갈 수 있습니다. 참여자와 이번 모임 손님으로 발언 순서를 섞고 "다음 사람"으로 넘깁니다. 진행 중에는 화면 아래에 남은 시간 알약이 떠 있습니다.
- **모임 기록 내보내기**: 밑줄(문단별 인용과 메모), 문단 메모(답글 포함), 토론 질문(체크 상태)을 마크다운 파일로 내려받거나 복사합니다.
- **있으면 좋은 기능**: 문단 공감(하트), 낭독 모드(SpeechSynthesis로 지금 읽는 문단부터 차례로 읽고, 읽는 문단을 표시하며 따라 스크롤합니다).
- **글 고치기에 강한 위치 보존**: 방의 글을 고치면 사라진 문단을 가장 비슷한 새 문단(글자 바이그램 유사도)에 연결해 메모·질문·밑줄을 옮깁니다. 그래도 찾지 못한 밑줄·메모는 읽기 화면 끝의 "위치를 잃은 밑줄·메모"에 모아 둡니다. 편집 화면에서 저장 전에 몇 개가 위치를 잃는지 미리 알려 줍니다.
- **편집 초안 보관**: 방 만들기·고치기 화면에서 저장하지 않은 입력은 초안으로 보관합니다. 상단 막대나 뒤로 가기로 다른 화면에 갔다가 오거나 새로고침해도 입력을 되살리고, 되살렸다는 안내와 "버리기" 버튼을 보여 줍니다. "취소"와 돌아가기 링크는 저장하지 않은 입력이 있으면 버릴지 먼저 묻습니다.

예시 글 두 편(「느리게 읽는 방」, 「창가 자리의 기록」)은 가상의 필자가 쓴 창작 에세이이며, 예시 속 인물(민지, 태오)도 가상입니다.

## 사용 방법

1. 서재에서 **새 방 만들기**를 누르고 함께 읽을 짧은 글을 붙여 넣습니다. 모임 일시와 출처, 내 이름과 색을 적고 저장합니다.
2. 읽기 화면에서 글을 끌어 선택하고 색을 누르면 밑줄이 그어집니다. 문단 오른쪽의 메모 버튼으로 문단 메모를, 물음표 버튼으로 토론 질문을 남깁니다.
3. 머리 막대의 **함께 읽기**에서 공유 링크를 만들거나 `.readroom.json` 파일을 내보내 함께 읽는 사람에게 보냅니다. 받은 사람도 밑줄과 메모를 더해 다시 보내면, 가져올 때 항목 단위로 합쳐집니다.
4. 모임 날에는 **진행**에서 단계 시간을 정하고 시작합니다. 끝나면 **함께 읽기 → 모임 기록**에서 마크다운으로 기록을 내려받습니다.

키보드로도 쓸 수 있습니다. 밑줄에 Tab으로 가서 Enter를 누르면 밑줄 카드가 열리고, Escape로 닫으면 제자리로 돌아옵니다. 캐럿 브라우징(F7)이나 화면 낭독기로 글을 고르면 선택 팝오버가 뜨고, Tab으로 색 버튼에 들어가 Enter로 밑줄을 긋습니다. 문단의 메모 버튼에서 Enter로 여백 메모를 열고, Escape로 닫으면 그 메모 버튼으로 돌아옵니다. 메모 입력칸에서는 Ctrl(⌘) + Enter로 저장합니다. 가져오기 확인 같은 대화상자가 떠 있을 때 Escape는 맨 위의 대화상자부터 닫습니다.

## 실행·빌드·테스트

Node.js 20.19 이상이 필요합니다.

```sh
npm install --no-audit --no-fund
npm run dev            # 개발 서버
npm run build          # 타입 검사 후 dist/에 빌드
npm run lint           # oxlint
npm run test:unit      # 도메인 로직 단위 테스트(node:test, 23개)
npm run build && PORT=4307 npm run test:smoke   # 헤드리스 Chrome 스모크 테스트
```

스모크 테스트(`tests/smoke.mjs`)는 빌드본을 미리보기 서버로 띄워 실제 사용자 흐름을 확인합니다. 방 만들기·고치기, 여러 서식에 걸친 끌어 선택 밑줄과 새로고침 뒤 위치 유지, 겹친 밑줄, 메모 스레드, 질문, 읽기 설정, 위치 복원, 공유 링크 왕복과 중복 방지·잘린 링크·긴 글 경고, 파일 병합(추가·삭제 전파·멱등성), 마크다운 기록, 두 탭 동기화와 알림 횟수, 가짜 시계로 돌리는 단계 타이머, 방 지우기 되돌리기, 설정(예시 지우기·전체 초기화·손상 데이터), 모바일 가로 넘침·터치 선택·아래 시트 메모를 다룹니다. QA에서 찾아 고친 문제의 회귀 시나리오(밑줄을 지운 뒤 새 선택, 키보드로 밑줄 긋기와 여백 메모 닫기, 프로필 이름 변경의 반영과 탭 간 동기화, 저장 공간 부족 시 가져오기·메모 저장, 큰 파일과 위험한 id 거르기, 다른 화면에 있을 때의 단계 알림)도 함께 돌립니다. 콘솔 오류가 하나라도 있으면 실패합니다.

`tests/screens.mjs`는 디자인 점검용 스크린샷 도구입니다. 미리보기 서버를 띄운 상태에서 `PORT=4307 node tests/screens.mjs`로 실행하면 `tests/artifacts/`에 주요 화면을 저장합니다.

## 기술 구성

- Vite 8, React 19, TypeScript 6(strict), oxlint, playwright-core(테스트)
- 서체: Pretendard Variable(`pretendard`), 고운바탕(`@fontsource/gowun-batang`) — 모두 자체 호스팅이며 외부 폰트 요청이 없습니다.
- 라우팅: 해시 라우팅(`#/`, `#/new`, `#/room/:id`, `#/room/:id/edit`, `#/settings`, `#/i/<공유 데이터>`)이라 서버 rewrite 설정이 필요 없습니다.
- 구조
  - `src/lib/`: 순수 도메인 로직 — 마크다운 문단 해석(`markdown.ts`), 밑줄 조각 나누기(`highlights.ts`), 선택 → 오프셋 변환(`selection.ts`), 위치 보정·글 수정 이관(`anchors.ts`), 병합·검증(`merge.ts`), 공유 링크 압축(`share.ts`), 단계 타이머(`session.ts`), 읽기 시간(`readingTime.ts`), 기록 마크다운(`exportMd.ts`), 알림음(`audio.ts`)
  - `src/store/`: localStorage 스토어와 탭 동기화(`rooms.ts`), 이 기기 전용 설정(`local.ts`)
  - `src/reader/`: 읽기 화면 부품(문단, 선택·밑줄 팝오버, 여백 메모, 패널, 진행 모드, 낭독)
  - `src/pages/`: 서재, 방 편집, 읽기, 설정 화면
- 크롬 조형과 아이콘은 모두 인라인 SVG·CSS 그라디언트로 그렸습니다. 이미지 파일이나 외부 네트워크 호출이 없습니다.

## 데이터 저장 방식과 개인정보

- 모든 데이터는 이 브라우저의 `localStorage`에만 저장됩니다. 키는 모두 `toyz-read-room:` 접두사를 씁니다(`rooms`, `profile`, `prefs`, `positions`, `sessions`). 방 데이터에는 스키마 버전(`schema: 1`)이 들어 있습니다.
- 저장된 값이 손상되었으면 앱이 죽지 않고, 원래 값을 `…:corrupt-<시각>` 키로 옮겨 둔 뒤 빈 상태로 시작합니다.
- 저장 공간이 모자라 저장하지 못하면 화면에만 남는 가짜 저장을 하지 않습니다. 바뀐 내용을 되돌리고 알림을 띄우며, 쓰던 메모·질문·방 글은 입력칸에 그대로 남겨 둡니다. 가져오기는 "반영했어요" 대신 실패를 알리고 아무것도 바꾸지 않습니다.
- 가져오기 파일은 8MB까지 받습니다. 공유 링크는 풀었을 때 16MB를 넘으면 열지 않아, 조작된 링크가 탭의 메모리를 다 쓰지 못하게 합니다. 공백이 든 id나 `__proto__` 같은 위험한 id는 가져올 때 걸러냅니다.
- 내 프로필 이름·색을 바꾸면 내가 참여한 방의 참여자 정보도 함께 바뀌어 예전 밑줄·메모 옆에도 새 이름이 보입니다. 같은 브라우저의 다른 탭도 바뀐 프로필과 읽기 설정을 따라갑니다.
- 서버로 아무것도 보내지 않습니다. 공유 링크의 데이터는 URL의 해시(`#` 뒤)에만 들어 있어 웹 서버 요청에도 실리지 않습니다. 다만 링크나 파일을 받은 사람은 방 전체(글, 밑줄, 메모, 질문, 참여자 이름)를 볼 수 있으니, 함께 읽을 사람에게만 보내 주세요.
- 설정 화면에서 예시 데이터 지우기, 전체 내보내기, 전체 초기화를 할 수 있습니다.

## 알려진 한계

- 실시간 동기화는 같은 브라우저의 탭 사이에서만 됩니다. 다른 기기·다른 사람과는 링크나 파일을 주고받아 합칩니다.
- 로그인이 없으므로 누구나 받은 방의 모든 항목을 고치거나 지울 수 있습니다. 병합은 신뢰하는 소모임을 전제로 합니다.
- 밑줄은 한 문단 안에서만 그을 수 있습니다. 여러 문단에 걸쳐 선택하면 첫 문단까지만 쓰고 그 사실을 알려 줍니다.
- 글을 크게 고치면 일부 메모·밑줄이 위치를 잃을 수 있습니다(읽기 화면 끝에 따로 모아 둡니다).
- 공유 링크는 글이 길수록 길어집니다. 긴 글은 파일로 공유하는 편이 안전합니다. `CompressionStream`을 지원하지 않는 아주 오래된 브라우저에서는 압축된 링크를 열 수 없습니다(파일은 열 수 있습니다).
- 낭독 모드의 목소리와 속도는 기기에 설치된 음성에 따라 다르고, 음성 합성을 지원하지 않는 브라우저에서는 낭독 버튼이 보이지 않습니다. 스모크 테스트는 낭독 상태 전환만 확인하며 실제 소리는 확인하지 않습니다.
- 브라우저가 소리 재생을 막으면(사용자 조작 없이 새로고침한 직후 등) 단계 종료 알림음 대신 화면 알림만 뜰 수 있습니다.
