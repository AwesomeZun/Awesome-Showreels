# MOOD FM

> 오늘의 기분으로 고르는 플레이리스트

기분에 주파수를 맞추는 작은 라디오 방송국이에요. 무드 패드를 끌거나 주파수 다이얼을 돌리면 화면의 색과 음악이 함께 바뀌어요. 음악은 브라우저 안에서 Web Audio로 실시간으로 만들어지고, 들은 무드는 색과 한 줄 메모로 일기에 남겨 달력·연간 픽셀·통계로 다시 볼 수 있어요.

toyz 마켓플레이스의 예시 프로젝트를 실제 앱으로 구현했습니다. 원래 소개는 "하루의 감정을 색과 음악으로 기록하는 사이드 프로젝트(React, Spotify API)"였고, 이 구현은 API 키 없이 동작하도록 Spotify 대신 Web Audio 생성 음악을 씁니다.

## 주요 기능

- **무드 선택**: 2축 무드 패드(가로 어두움→밝음, 세로 차분→에너지)를 드래그하거나, 8개 스테이션(고요·새벽·비·집중·몽글·맑음·산책·들뜸)을 FM 다이얼에서 골라요. 좌표마다 OKLCH로 섞은 2~3색 그라디언트가 화면을 물들이고, 글자색은 WCAG AA 대비를 자동으로 맞춰요.
- **생성형 음악 엔진**: 무드 좌표가 템포, 모드(에올리안~리디안), 마르코프 코드 진행, 음색(패드·일렉피아노풍·플럭·벨), 리듬 밀도, 필터, 리버브·딜레이 양, 질감 레이어(비닐 노이즈·빗소리)를 정해요. 끊김 없이 계속 만들어지고, 무드를 바꾸면 파라미터가 부드럽게 옮겨 가요.
- **플레이어**: 재생·일시정지(페이드 인·아웃), 음량, 다음 곡(새 시드로 변주), 곡명·키·BPM·시드 표시, 슬립 타이머(15·30·60분, 마지막 20초 페이드아웃. 일시정지한 사이에 끝나면 타이머만 풀리고, 다시 재생해도 곧바로 꺼지지 않아요), 주파수에 반응하는 Canvas 스펙트럼.
- **내 플레이리스트 링크**: 스테이션별로 좋아하는 외부 링크(제목·URL)를 저장하고 새 탭으로 열어요. 무드 키워드로 YouTube·YouTube Music·Spotify·Apple Music·Bandcamp 검색 결과 페이지를 열거나 링크로 저장할 수 있어요. 음악 서비스 API와는 연동하지 않아요.
- **감정 일기**: 지금 무드(좌표·색·스테이션)와 한 줄 메모를 기록해요. 마지막 기록 이후 들은 시간이 자동으로 붙고, 하루에 여러 번 남길 수 있어요. 무드 좌표와 메모를 고치거나 지울 수 있고, 지운 직후에는 되돌릴 수 있어요.
- **기록 보기**: 날짜 칸이 그날의 색으로 칠해지는 월간 달력, 연간 픽셀 보기(한 줄이 한 달), 통계(가장 잦은 무드, 요일·시간대 경향, 에너지·밝기 추이 SVG 차트와 표 보기). 날짜를 고르면 그날의 무드로 다시 들을 수 있어요.
- **오늘의 무드 카드**: 오늘 기록(또는 지금 무드)으로 1080×1350 이미지를 Canvas로 그려 PNG로 저장해요.
- **데이터**: JSON 내보내기·가져오기(합치기·바꾸기), 최근 6주치 예시 기록 넣기·지우기, 전체 초기화(확인 후, 되돌리기 가능).
- **화면**: 주파수의 소수점이 온에어 램프를 겸해 재생하면 코랄로 켜져요. 무대에는 1px 크롬 테두리를 두르고, 일기는 큰 날짜 숫자와 그날의 색 띠를 세운 에디토리얼 배치로 보여 줘요. 태블릿 폭에서는 무드 패드가 가로로 넓어져요.
- **그 밖에**: 모바일 오디오 잠금 해제, 백그라운드 탭 대응(선행 예약 3초 + 오디오 워클릿 시계), 미디어 세션(잠금 화면·키보드 미디어 키), 시간대별 추천 스테이션.

## 사용 방법

1. 온에어 화면에서 크롬 재생 버튼을 눌러요. 모바일 브라우저는 사용자가 버튼을 눌러야 소리가 나요.
2. 무드 패드를 끌거나(키보드: 퍽에 포커스 후 화살표, Shift로 크게), FM 다이얼의 바늘을 끌거나(키보드: 좌우 화살표, Page Up·Down으로 스테이션 이동) 스테이션 버튼을 눌러 주파수를 맞춰요.
3. 곡이 마음에 들지 않으면 '다음 곡'을 눌러 같은 무드의 다른 변주를 들어요.
4. '오늘의 기록'에 한 줄 메모를 쓰고 '기록하기'를 누르면 지금 무드가 일기에 남아요. 패널 아래 24시간 줄에 기록한 시각과 그때의 색이 찍혀요.
5. 아카이브에서 색이 칠해진 날을 골라 '그날의 무드로 다시 듣기'를 눌러 보세요.

## 실행·빌드·테스트

Node 20.19 이상이 필요해요.

```sh
npm install --no-audit --no-fund
npm run dev          # 개발 서버
npm run build        # 타입 검사 + 프로덕션 빌드(dist/)
npm run lint         # oxlint
npm run test:domain  # 도메인 순수 함수 검증(node만 필요)
PORT=4312 npm run test:smoke   # 빌드 결과를 미리보기 서버로 띄워 헤드리스 Chrome으로 사용자 흐름 24개를 확인
PORT=4312 npm run test:audio   # 스테이션별 오프라인 렌더링으로 음량·클리핑·노드 정리·전환 잡음 확인
PORT=4312 node tests/shots.mjs # 주요 화면 스크린샷(tests/artifacts/)
```

스모크·오디오 테스트는 먼저 `npm run build`가 되어 있어야 하고, 설치된 Chrome을 헤드리스로 씁니다(`CHROME_PATH`로 다른 실행 파일을 지정할 수 있어요).

## 기술 구성

- Vite 8, React 19, TypeScript 6(strict), oxlint, playwright-core(테스트 전용). 런타임 의존성은 React와 Pretendard 글꼴(자체 호스팅)뿐이에요.
- 해시 라우팅(`#/`, `#/diary`, `#/archive`, `#/card`, `#/data`)이라 서버 rewrite 설정이 필요 없어요.
- 폴더 구성
  - `src/domain/`: 색(OKLab·OKLCH·대비), 무드 파라미터, 음악 이론(스케일·마르코프 코드 진행·멜로디·드럼), 날짜(로컬 기준), 통계, 검색 링크, 가져오기 검증, 예시 데이터. 모두 순수 함수예요.
  - `src/audio/`: `engine.ts`(시퀀서와 신호 흐름, 오프라인 렌더링도 같은 코드), `instruments.ts`(악기 목소리와 노드 정리), `buffers.ts`(리버브 임펄스·비닐·빗소리 절차 생성), `radio.ts`(실시간 재생 제어), `worklet.ts`(오디오 스레드 시계), `diag.ts`(오프라인 진단).
  - `src/app/`: 저장소(localStorage), 무드·라디오 연결, 라우터, 알림.
  - `src/components/`, `src/pages/`: 화면.

### 음악 엔진

- 스케줄링은 `AudioContext.currentTime` 기준 16분음표 단위 선행 예약이에요. 보이는 탭은 0.2초, 숨겨진 탭은 3초 앞까지 예약하고, 타이머와 오디오 워클릿 메시지 둘 다로 스케줄러를 깨워요.
- 편곡: 4코드 진행을 두 번 반복한 뒤 새 진행으로 넘어가고(두 번째 반복은 선율을 살짝 바꿔 되풀이), 곡 처음은 패드만 → 드럼 → 멜로디 순으로 들어오며, 16마디마다 드럼을 두 마디 쉬어요.
- 신호 흐름: 악기 버스 → 톤 필터 → 컴프레서 → 스테이션별 음량 보정 → 리미터 → 소프트 클리퍼 → 곡 전환 게인 → 트랜스포트(페이드) → 음량. 스테이션별 보정값은 오프라인 렌더링으로 RMS를 재서 맞췄어요(스테이션 간 차이 약 1dB, 피크 0.85 이하).
- 무드를 크게 옮기거나 모드 경계를 넘으면 다음 마디에서 새 코드로 넘어가요. 이때 길게 끌던 이전 패드·베이스는 새 코드가 들어오는 순간부터 부드럽게 줄여, 이전 모드의 화음이 새 코드와 몇 초씩 부딪히지 않게 해요.
- 모든 음은 시작할 때 0에서 올라가고 끝날 때 0 가까이 내려간 뒤 멈추며, 멈춘 목소리는 `onended`에서 연결을 끊어 정리해요. 90초 렌더링에서 목소리 2,145개를 만들고 끝에 22개만 남는 것을 확인했어요.

## 데이터 저장과 개인정보

- 일기·링크·설정은 이 브라우저의 `localStorage`(`toyz-mood-fm:store`, 스키마 `version: 1`)에만 저장돼요. 서버로 보내지 않고, 분석 도구나 외부 요청도 없어요.
- 저장된 값이 손상되면 읽을 수 있는 부분만 불러오고, 원본은 `toyz-mood-fm:store:corrupt-backup`에 남긴 뒤 화면에 안내해요. 통째로 깨진 경우뿐 아니라 일부 항목만 걸러 낸 경우에도 원본을 남겨요.
- 같은 브라우저에서 탭을 여러 개 열어 두면, 한 탭에서 쓴 일기·링크가 다른 탭에도 바로 반영돼요. 오래 열어 둔 탭에서 무드만 바꿔도 다른 탭의 기록을 덮어쓰지 않아요. 무드·음량 설정은 탭마다 따로 움직여요.
- 무드 카드 PNG와 JSON 백업도 기기 안에서 만들어져 바로 내려받아져요.
- 외부로 나가는 건 사용자가 직접 누른 링크(저장한 플레이리스트, 음악 서비스 검색)뿐이고, 새 탭에서 `noopener`로 열려요.

## 알려진 한계

- 음악 서비스(Spotify 등)와 API로 연동하지 않아요. 검색 결과 페이지를 여는 링크만 제공해요.
- 생성 음악은 규칙·마르코프 기반이라 아주 오래 들으면 비슷한 느낌이 반복될 수 있어요. 곡명은 시드와 스테이션으로 만든 이름이에요.
- 검증은 macOS의 헤드리스 Chrome(데스크톱·모바일 에뮬레이션)에서만 했어요. iOS Safari 실기기에서는 확인하지 못했어요. 무음 스위치 대응(`navigator.audioSession`)은 지원하는 Safari에서만 동작해요.
- 일부 모바일 브라우저는 화면이 꺼지거나 앱을 전환하면 웹 오디오 자체를 멈춰요. 선행 예약은 탭이 뒤로 가도 끊기지 않게 하는 장치이고, 운영체제가 멈추는 경우까지 막지는 못해요.
- 들은 시간은 재생 중인 이 탭에서만 재고, 기록할 때마다 0부터 다시 세요.
- 기기 사이 동기화는 없어요. JSON 내보내기·가져오기로 옮겨 주세요.
